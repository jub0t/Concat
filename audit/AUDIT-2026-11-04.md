## 5. Open findings, High

- **P1. `main` has still not had a green CI run since 24 October.** *Verified.*
  - The last finished run (`7279a2d4`) failed in two jobs: clippy on one
    collapsible `if`, and 15 Windows tests. HEAD (`8c86502`) answers 14 of
    the 15, and the clippy lint.
  - The 15th, `a_shaky_shot_is_measured_and_held_still`, failed at
    `concat-host/tests/stabilize.rs:310`:
    `assert!(against_export < 2.0)`. That is the monitor drawing a
    stabilised frame differently from the export by more than the encoder
    should account for. HEAD doesn't touch it, so the next run will likely
    fail again on it.
  - The probable cause is the Windows export's encoder changing under it
    (Media Foundation or OpenH264 in place of x264). That would mean the
    threshold is wrong for the new encoder, not that the monitor is wrong.
    But it is also the only check that monitor and export agree on a
    stabilised clip, so it shouldn't be loosened without measuring.
  - **Fix:** print `against_export` per frame on the Windows runner, against
    the encoder it names. Then either set the bound per encoder family, or
    write the test's export with a fixed lossless codec so it measures the
    compositor alone.
  - Then let one full CI run, one phone run and one Nix run finish green on
    the same commit before tagging.

- **P2. A ten-bit or HDR HEVC export is offered where nothing can write it,
  and fails.** *Verified in code.*
  - `ten_bit_available` is true when any ten-bit encoder is *linked*
    (`concat-media/src/encode.rs:299-301`). On Windows and Linux the only
    linked ten-bit HEVC encoders are NVENC, QSV and AMF, since Kvazaar and
    Media Foundation take eight bits only (`:768-781`). The desktop FFmpeg
    builds link all three whatever GPU is in the machine.
  - `encodable` counts a vendor's encoder as there without opening it
    (`:666`), so the sheet's `hdr()` passes (`concat/src/panes/export.rs:412-426`).
  - The export then asks for `linked(true, true)`: NVENC, QSV, AMF, each of
    which fails to open, and it fails (`encode.rs:1594-1610`).
  - The #491 software rerun for a chip that stalled part way through takes
    the same list less the hardware, which leaves nothing at ten bits.
    Before x265 left, both roads ended on it.
  - **Who meets it:** an HLG or PQ timeline (iPhone footage is HLG), or the
    ten-bit switch, exported to HEVC (or to H.264, whose HDR check is made
    on HEVC) on a desktop without a working NVIDIA, Intel or AMD encoder.
    That includes VMs, older PCs, and most Linux machines without NVIDIA:
    the Linux list has no VAAPI, and QSV/AMF there need vendor runtimes.
    v0.2.8 has 11 856 Linux downloads.
  - `8c86502` makes the tests skip in exactly this case
    (`ten_bit_only_on_hardware`, `encode.rs:263-266`). The product path has
    no such handling.
  - **Fix:**
    - Treat ten-bit HEVC as available only once a vendor encoder has opened
      for it (`probed`), as `hardware_encoded` already does.
    - Otherwise, tone-map to SDR as a phone does, and say so on the sheet.
      Or offer ten-bit AV1, which SVT-AV1 writes on the CPU.
    - On the software rerun, drop to eight-bit SDR rather than fail.

- **O1, O2, O4** are carried, as in section 4.

## 6. Open findings, Medium

- **P3. The API's write roots don't cover saving a project opened by
  path.** *Verified in code.*
  - The server and MCP transports call `restrict_writes_to`
    (`concat-server/src/lib.rs:219`, `concat-mcp/src/backend.rs:191`), and
    its doc says writes must land under a root
    (`concat-api/src/lib.rs:360-366`).
  - `open` takes any path (`:537-544`). `save`, `apply` and `close` with
    `save: true` then write that project's `concat.json` in place
    (`:580-608`), and none of them calls `writable`.
  - The impact is bounded: the caller needs the token, and the write is a
    Concat document into a folder that already holds one. But a confined
    caller can rewrite any project the user can read.
  - **Fix:** in `open`, refuse a project outside the roots when roots are
    set, or open it read-only and refuse `save`/`apply`.

- **M3 (from X-H1). Saved transitions render differently in 0.2.9.**
  *Verified in code.*
  - An old `transition_in` is made a clip centred on its cut, no longer
    than either side (`concat-export/src/lib.rs:733-791`).
  - The 0.2.8 rule that leaned a short-handled transition after the cut is
    gone, and so is the push over a held frame turning into a dissolve.
  - This is a deliberate choice, and the new model is tested. But every
    project with a transition will look different, and no test pins the old
    look.
  - **Fix:** say so in the release notes.

- **P4. Version 0.2.9 is stamped before it exists.** *Verified.* The README
  badge (`README.md:15`), every translated README and the installers say
  0.2.9, while the newest release is v0.2.8. Anyone building `main`, or
  reading the README, sees a version nobody can download. That is fine if
  0.2.9 is cut from the next green commit; otherwise move the bump to the
  release commit.

- **Triage.** *Verified.* #533, #556, #561 and #600 still have no comment,
  as do all 6 issues opened since 3 November (#657, #658 among them).
  Contributor PRs #646 (an API export-progress fix) and #620 (Halation on
  DX12) have had no review.

- **Carried:** E-M1 (reader slack counted in output frames, while the pool
  counts source frames) and W-M7 (every focus-in stats every media file on
  the UI thread, which waits on SMB timeouts for footage on a lost share).
  D-M1: 0 of 141 clean-room items done, 19 274 outside lines.

## 7. Open findings, Low

- **L1. The export thread panics if the encoder's thread dies before it
  reports.** `concat-export/src/lib.rs:2021`:
  `Err(_) => panic!("the encoder's thread ended before it said whether it opened")`.
  A panic inside FFmpeg's open on that thread turns into a second panic on
  the export's, where an `Err` would let the window say what happened.
  *Reasoned.*
- **L2. A loop-invariant test left by the clippy fix.**
  `concat-export/src/lib.rs:757-761` checks `cuts.is_empty()` once per clip,
  then again at `:762`. It is correct, but it reads as if the condition
  depended on the clip. `if cuts.is_empty() { clear; return; }` says what it
  means.
- **L3. The Windows junction goes through `cmd /C mklink /J`.**
  `concat-host/src/dirs.rs:196-214`. cmd re-parses its command line, and
  Rust quotes an argument only when it holds a space. A profile path with
  `&`, `^` or `%` and no space breaks the junction, and the text after `&`
  runs as a command. The path is the user's own, so this isn't an attack
  surface. It only runs when adopting a main build's folder. *Reasoned.*
- **L4. A transition clip counts toward the timeline's length.**
  `Timeline::duration` takes every clip's end (`concat-project/src/model.rs:3076-3081`).
  A transition dropped over the end of the last shot lengthens the export by
  the part that runs past it. Over nothing, it draws the package over the
  canvas. That's arguably right for a fade to black, but it should be a
  decision. *Reasoned.*
- **L5. The Audio page's sound list is read from an unpinned branch.**
  `concat-host/src/models.rs:51-52` reads `manifest.json` from
  `concatapp/assets` `main`, and the digests come from that same file. That
  makes the check a guard against torn downloads, not against whoever can
  push to that repository. The models, by contrast, are pinned by revision
  and digest in code (`concat-speech/src/chatterbox.rs:116-180`,
  `concat-host/src/models.rs:593-609`).
- **L6. No way back from 0.2.9.** The first save rewrites a version 1
  project as version 2, which 0.2.8 refuses. That is the intended trade, but
  it belongs in the release notes, next to M3.
- **L7. Thirteen `unsafe` sites have no SAFETY note within eight lines.**
  These are FFI declarations, JNI entry points, and the crash handler's
  `siginfo` readers (`concat-host/src/crash.rs:188-243`). None looks wrong.
  A one-line note each keeps the sweep at zero.
