# Concat audit, 23 September 2026

Where the codebase stands one week after the 16 September proposal landed.
Every crate, every feature and the engineering process were read and scored
on the same seven scales, plus security, testing and documentation where they
turned out to matter. Every finding names a file and a line. The sibling
`AUDIT-2026-09-23-QUICK.md` is the same audit as a one-screen scorecard.

**How it was done.** Nine reviewers each read one part of the tree in full
(the crates, the window's Rust, the Slint UI, the API and transports, the
model crates, and the tests, CI, build and docs), scored it and reported
findings with locations. The headline findings were then re-verified by hand
against the code before they went in here. Line counts, test counts and the
unsafe, unwrap and panic tallies come from the tree; `cargo fmt --check`,
`cargo clippy --workspace --all-targets`, `cargo test --workspace` and
`cargo run -p concat-perf --release -- --check` were run on this machine
(Apple Silicon, macOS 26). The app itself was not launched: "user
likeability" is judged from what the UI code does, not from users.

**Scale.** 0 to 10. 8 and up means "keep doing this"; 5 to 7 means "works,
with known debt"; 4 and under means "will bite at the next order of
magnitude, or already bites".

## 5. Findings, by severity

Each carries the location and, where I re-verified it by hand, **(verified)**.

### Critical

1. **A corrupt document opens as an empty project, and the next save
   overwrites it.** (verified) `Session::open` matches `Err(_)` from
   `projects::read_document` and builds an empty editor
   (`concat-host/src/session.rs:95`); that function returns the same `Err` for
   "file not found" and for a JSON parse failure (`projects.rs:211-215`). The
   comment nine lines above says a corrupt document is an error. Saves are
   atomic with fsync (`projects.rs:168-190`), so the window is narrow: a power
   cut, a sync tool or an external edit. When it happens it is silent data
   loss.

2. **A panicking scheduler job wedges the scheduler.** (verified)
   `prefetch.rs:355` runs `job()` with no unwind guard. A panic skips the
   decrements at 357-363, `running` never drops, `drain` waits forever
   (`prefetch.rs:307`) and background lanes stay blocked once the counters sit
   at their limit. Failed thread spawns are also ignored (`prefetch.rs:194`).

3. **Worker results land in whichever project is open.** `Studio::handle`
   (`concat/src/studio.rs:5376-5429`) checks no project identity, and
   `close_project` (`studio.rs:5308`) does not reset the export, captions or
   speech panes. A probe, a caption run or a speech job started in project A
   delivers into project B (`panes/media_bin.rs:153`, `panes/captions.rs:132`,
   `panes/speech.rs:339`). ARCHITECTURE §5 claims the opposite.

4. **The API lets a token holder write anywhere and send anything.**
   (verified) `preview.frame` creates folders and truncates any path
   (`concat-api/src/lib.rs:707-714`); `export.run`, `project.create` and
   `template.instantiate` take any path. Width and height are only checked
   for zero (`lib.rs:499-502`), so 65535×65535 asks for 17 GB on the Hub
   thread. The JSON transport reads lines of unbounded length before
   authentication, spawns two threads per connection with no cap and no
   timeout, and queues output in an unbounded channel
   (`concat-server/src/json.rs:63,117,193`). The token itself is right:
   128 bits, constant-time compare, required on loopback.

5. **The window and the Remote page are two engines on one folder.**
   (verified) Settings › Remote starts `Server::start(config, Api::new)`
   (`concat/src/panes/settings.rs:403`): its own session registry and its own
   exporter. An edit from either side is overwritten by whoever saves last,
   and "one export at a time" no longer holds across the two.
   `Api::exporter()` exists for sharing and nothing calls it. The §7 diagram
   showing the window over the API is wrong.

6. **Model downloads are unverified and unpinned.** (verified) 20 of 23 rows
   in `models/manifest.toml` have an empty `sha256`; `verify` accepts an empty
   digest (`concat-host/src/models.rs:289-291`); 18 upstream URLs point at
   `resolve/main`. The source list includes a mirror and a user-set base URL
   (`models.rs:149-180`), and a dropped transfer resumes with a Range request
   against the *next* source (`models.rs:216-219`), relying on the digest to
   catch a splice.

### High

7. **A hostile package is not really refused.** (verified that `trial` has
   no production caller) `WgpuCompositor::trial` is only called from tests.
   The loop check asks only whether a `break` token exists
   (`concat-effects/src/shader.rs:507-549`); binding types are never checked;
   validation uses `Capabilities::all()` (`shader.rs:614`). A pipeline that
   fails to build does so outside any error scope (`gpu.rs:1091`), which in
   wgpu is a panic.

8. **Undo's structural sharing is defeated by every ripple.** (verified)
   `clips_mut()` calls `Arc::make_mut` on every clip before the caller filters
   (`concat-project/src/model.rs:1966`); ripple trim, ripple delete, freeze
   and fill-slot use it (`commands/clips.rs:245,468,596,653`,
   `commands/media.rs:105`). The only sharing test covers `UpdateClip`.

9. **The stream's start time is ignored.** (verified: no reference in the
   crate) Timestamps are used raw (`decode.rs:743`) and turned straight into
   frame indexes (`pool.rs:364`). MTS and other camera files that start at a
   non-zero time will be offset in the pool, the paced export and the
   duration clamp. Inferred from the code, not reproduced.

10. **Darken and Lighten are wrong at partial opacity, on both paths.**
    (verified) Both compute `min(colour·α, ground)`
    (`compositor.rs:258-259`, `gpu.rs:421-430`): a white Darken layer at 30 %
    turns a mid-grey ground dark. Parity cannot catch it because both agree.

11. **The UI thread scans every media item on every pointer event.**
    (verified) The `handler!` macro calls `refresh_art()` after each callback
    (`concat/src/lib.rs:373`), including the lanes' hover and drag stream.
    That loops over all media calling `proxy::ensure` (two `stat` calls each,
    `studio.rs:2010-2030`) and decodes cached JPEGs synchronously. Separately,
    playback runs a full `publish_chrome` about 30 times a second
    (`host.rs:197`, `studio.rs:1905`), rebuilding every bin row, both menus and
    the recents list each time.

12. **`main` is red, and CI never compiles macOS or Windows until a tag.**
    Today's four CI runs on `main` fail at `cargo fmt --check` (8 files),
    which hides six failing tests behind it (§1.2). `build-app.yml` is
    `workflow_call` only; `ci.yml` runs on `ubuntu-latest`; `release.yml`
    does not require CI to pass. The GPU parity suite returns early with no
    adapter (`gpu/tests.rs:20-23`) and the runner installs none, so the
    parity row in ARCHITECTURE §8 is enforced only on developers' machines.
    No workflow runs `concat-perf --check`; 9 of its 13 scenarios never run
    in CI.

### Medium

13. **Clamps live in four places and disagree.** Commands re-implement
    `Clip::tidy` (`commands/properties.rs:28-37,340-355`); `TextStyle::tidy`
    runs only on load (`model.rs:1418`); the minimum transition length is
    applied only in tidy; `SetClipKey` leaves offset and rotation unclamped
    (`properties.rs:198`). A document can change on save and reopen. The
    speed range is written three times (`model.rs:1090`,
    `concat-core/src/retime.rs:27`, `concat-media/src/audio.rs:35`).

14. **The end-to-end suite checks timing, not looks.** It samples the centre
    pixel and maps colour to a source second (`tests/export.rs:305-323`),
    which proves cuts, trims, speed and reverse. Transitions, effects, keys,
    transform, crop, blend, fades, titles and adjustment layers assert only
    length and sound (`export.rs:915-1064`).

15. **Caches with no bound.** `cache/proxy` and artwork are never swept
    (`proxy.rs:16` says otherwise; `media.rs:323`); frames pinned by the
    prefetcher are neither deduplicated nor capped and `Monitor::prefetch`
    keeps adding while paused (`prefetch.rs:243,266`, `preview.rs:255`); the
    8 warm readers each decode with every core (`pool.rs:531`,
    `decode.rs:651`) outside the byte budget; on the GPU, `run_passes` claims a
    fresh full-size target per pass (`gpu.rs:1453`, about 133 MB each at 8K)
    and the LUT and reveal caches are never evicted (`gpu.rs:198-201`).

16. **Per-frame copies and graph rebuilds.** Every paced frame is deep-copied
    before filtering (`decode.rs:934,944,994`), then filtered, then copied row
    by row into a `Frame` (`decode.rs:873`); a hardware frame adds a download.
    On the monitor path every treated frame builds, parses and validates a
    fresh filter graph (`treat.rs:85-126`).

17. **The Hub thread does heavy work in line, and event fan-out holds a
    mutex.** Preview decode and composite, probes and title painting run on
    the one thread that serves every caller (`hub.rs:71`, `lib.rs:505,396`).
    The gRPC subscriber does a `blocking_send` into a channel of 64 while the
    subscribers mutex is held (`grpc.rs:70-74`, `hub.rs:52`): one slow client
    stalls the export thread.

18. **ONNX Runtime is probably linked twice** (sherpa-onnx's static copy plus
    `ort` 2.0.0-rc.13 through vision and Chatterbox), and CoreML is registered
    with default options and an aspect-dependent input shape
    (`concat-vision/src/runtime.rs:141`, `segment.rs:115`). Needs profiling.

19. **Speech is reachable only from the window.** Only `concat` depends on
    `concat-speech`, so captions and TTS have no API, CLI or server verb;
    "three ways in" does not hold for them. Also missing verbs: enhance,
    proxies, package install, cache clear, a jobs list, CBR export.

20. **The title rasteriser copies the whole font file per render** and draws
    on a frame-sized canvas it then un-premultiplies pixel by pixel
    (`concat-text/src/lib.rs:268-279,529-539`). With a CJK `.ttc` that is tens
    of megabytes per animated frame.

### Low

21. **UI facts that are wrong or stale.** Settings says H is "Flip
    horizontally" (`ui/dialogs/settings.slint:671`) while H is the pan tool
    (`app.slint:418`); it lists 3 of about 27 bindings. Tooltips show ⌘ on
    every platform (`ui/timeline/tray.slint:127,134`). README says twelve
    languages; there are 14 files. Two lane colours ignore the theme
    (`lanes.slint:792,835`). The window minimum is 900×560 while Android is
    listed as supported.

22. **Dead Slint still imported.** `ui/demo/` (495 lines) is unreachable, yet
    `EffectData` is imported from it by `app.slint:21`, `editor.slint:4` and
    `workspace/config-pane.slint:9`.

23. **Stale docs.** ARCHITECTURE §8 says 429 tests in 75 files (544 in 82);
    §1's crate map omits speech → media; §7's diagram puts the window over the
    API; `src/README.md:115` says `mobile.yml` runs on push (it does not);
    `release.yml:13` describes archives the build does not ship;
    `CONTRIBUTING.md:43` calls `test/` fixtures (it is Python prototypes).
    Newcomer setup omits ONNX Runtime, libclang, ALSA and GTK.

24. **Small hygiene.** 8 files fail `cargo fmt --check`. `core::Project`
    (`timeline.rs:500`) is dead. `missing_media` does disk IO inside a crate
    that must build for wasm (`model.rs:1896`). The CLI's `serve` parks
    forever and never removes its Unix socket (`concat-cli/src/main.rs:226`).
    `lib.rs:23` in the window uses `slint::private_unstable_api`. Pipelines
    are keyed by `id@version`, so a WGSL edit without a version bump keeps the
    stale pipeline (`shader.rs:417`).

## 6. What is good, and should stay that way

- **The layering.** Every arrow points one way. FFmpeg is only in
  concat-media; ONNX Runtime is only behind `concat-vision/src/runtime.rs`;
  concat-core has no dependencies and builds for wasm.
- **`FramePlan`.** Geometry and shading are computed once for both
  compositors (`plan.rs:140-416`), so placement and weighting cannot drift.
- **The document.** Commands are the only write path; snapshots share through
  Arc; gestures fold into one step; no-ops record nothing; batches are
  all-or-nothing; unknown fields survive a round trip; migrations are a table.
- **Hardware decode.** Reference-counted device, `get_format` fallback, a
  failed download reopens in software and seeks back to the exact frame,
  with tests that the frame count and timing match.
- **Package hygiene at load.** `deny_unknown_fields`, every chain rendered at
  its defaults, minimum and maximum, an FFmpeg filter allowlist, LUT paths
  held to the folder, the `concat.` namespace reserved.
- **The API contract.** Every verb is JSON named `area.verb`; gRPC wraps the
  same JSON; the docs match the code on every method spot-checked.
- **The window's pane pattern.** State + `Msg` + `update` + `data`, with the
  pane taken out during `update`; the monitor keeps one request in flight and
  builds its texture on the event loop on purpose.
- **Model fetching.** `.part` files, staging, rename into place, a
  compiled-in fallback cutout model, licences recorded for every model.
- **Tests that check behaviour.** Synthetic media coloured by source second;
  SSIM parity; migration tests against v1 documents; token handshake tests
  over TCP and gRPC.

within the week: the bug-fix pass, structural-sharing undo, `Clip::blank` and
`Clip::tidy`, `resolve.rs`, the tolerant reader with migrations, keys that
stay on their instant, ten panes behind one `Msg` loop, the source cache and
scheduler, `FramePlan` with parity, hardware decode, timeline virtualisation
and the loopback token. The tree is now the shape the proposal drew.

What that week did not buy is enforcement. Almost every serious finding here
is a stated rule the code does not yet hold: a corrupt document is an error
(it is not), a hostile package is refused (it is not tried), clamps live in
one place (four), stale results are dropped in one place (nowhere), publish
by diff (rows are rebuilt), one engine handle (two). The debt has moved from
structure to bounds and guarantees, which is the right direction, and is
cheaper to pay.

**Recommended order.** Each line is a day or a few, and each closes a
finding above.

1. Correctness trio: `Session::open` distinguishes not-found from parse
   error; `catch_unwind` with a counter guard around scheduler jobs; a
   session epoch captured in `spawn` and checked in `deliver`. (1, 2, 3)
2. Server limits and a root allowlist: line length cap, pre-auth timeout,
   connection cap, bounded outbox, bounded preview and export sizes,
   canonical-path check against configured roots. Hand the Remote server the
   window's exporter and sessions. (4, 5)
3. Fill every `sha256`, pin upstreams to commits, reject an empty digest in
   release builds, generate the five model tables from the manifest. (6)
4. Run `trial` at install at a realistic size, wrap pipeline creation in an
   error scope that disables the package, check binding types, key pipelines
   by source hash. (7)
5. `clips_where(pred)` in place of `clips_mut`, with `ptr_eq` tests for
   ripple and freeze; one clamp pass after every command; subtract
   `start_time` in one place; fix Darken and Lighten as
   `mix(ground, min(colour, ground), α)`. (8, 9, 10, 13)
6. Art refresh only on revision change; targeted publish from `deliver`;
   cache treat graphs by spec and size; `av_frame_ref` instead of deep
   clone; sweep proxy and artwork. (11, 15, 16)
7. CI: macOS and Windows `cargo check` plus engine tests; lavapipe on Linux
   with parity required; `concat-perf --check` as a step; release depends on
   CI. Fix the stale docs in the same pass. (12, 23)

After those, the architectural follow-ups in ARCHITECTURE §10 stay in their
order: the plan filled by the export, source textures pooled, zero-copy
hardware frames, one texture per track, native scalers behind Enhance,
multi-pass packages.

## 8. Caveats

Scores are judgements over code, calibrated across reviewers but not
measured against users or against another editor. Performance findings are
from reading hot paths plus the perf table; the window's repaint was not
measured. The OS-side claims in §10 of ARCHITECTURE (macOS 26 scalers, the
Windows super-resolution API) were not checked. Findings marked (verified)
were re-read by hand; the rest rest on one reviewer's reading and a line
number you can open.
