# Concat audit, 28 September 2026

Where the codebase stands five days after the 23 September audit, on the day
0.2.5 shipped. Same method, same seven scales, same reviewers' split, and
every one of the 24 findings from last time re-verified against today's
tree. Every finding names a file and a line. The sibling
`AUDIT-2026-09-28-QUICK.md` is this audit as a one-screen scorecard.

**How it was done.** Nine reviewers each read one part of the tree in full
(core and project; media; render and effects; export and host; the window's
Rust; the Slint UI; the API, server and CLI; speech, vision, text, Android
and the model manifest; tests, CI, build, docs and release), re-verified the
23 September findings assigned to them, scored their part and reported new
findings with locations. The headline items were re-checked by hand against
the code before they went in here. Line counts, test counts and the unsafe,
unwrap and panic tallies come from the tree; `cargo fmt --check`,
`cargo clippy --workspace --all-targets`, `cargo test --workspace` and
`cargo run -p concat-perf --release -- --check` were run on this machine
(Apple Silicon, macOS 26). The app itself was not launched.

**Status of this document.** Written the same morning. The core/project,
export/host and API/server/CLI reviews are in and folded in below; the
media, render/effects, window, Slint, models and CI/docs reviews were still
running when this was written, so those crates' scores are marked
*provisional* (carried from 23 September, adjusted only where a hand check
justified it). Each of those sections is replaced as its review lands. The
check suite, the perf table and the CI history are complete.

**Scale.** 0 to 10. 8 and up means "keep doing this"; 5 to 7 means "works,
with known debt"; 4 and under means "will bite at the next order of
magnitude, or already bites".

The tree grew by an eighth in five days and lost weight in the right
places: concat-project shed its 800-line preset-animation module, and
concat-effects shed 59 format 1 picture packages (WGSL lines fell from
2 205 to 1 744 while the crate's Rust grew by half for the format 2
contract, multi-pass and probes). concat-render doubled: the CPU compositor
became a test oracle and the GPU one took on linear light, HDR, scopes and
the texture cache. The window's Rust grew by a fifth, most of it in
`studio.rs`, which is now 9 461 lines (7 484 on the 23rd).

Outside test modules the workspace holds 137 `unwrap`/`expect` calls, 34 of
them in the perf harness and 42 in concat-media's FFI, and 13 `panic!`
family calls, 7 of which are `unreachable!` routing arms in concat-project.

57 looks, 20 transitions; 25 audio packages still on FFmpeg chains, by

**Two window tests fail locally; CI is green.** Both failures are tests
that translate a string and got German where they expected English:
`format::tests::phrases_are_coarse` sees "gestern" for "yesterday"
(`concat/src/format.rs:502`) and
`panes::speech::tests::a_voice_name_reads_as_a_person_would_say_it` finds no
"American" in a voice's detail (`panes/speech.rs:672`). Since `fc09a61` the
locale is process-wide and the locales test in the same binary loads every
shipped file in turn, `de` first; the two tests read whichever locale the
other thread left behind. Confirmed: both pass when run alone, and the whole
window suite passes with `--test-threads=1`. A test-isolation bug, not a
product one. The end-to-end export suite (11 tests, 21 s), the parity suite
(85 tests, 39 s) and every engine crate pass.

five times slower than software (316 against 1 626) because the frame is
downloaded and converted on the CPU after the chip decodes it, the
zero-copy item of ARCHITECTURE §10.

## 6. New findings, by severity

No new critical. Each carries a location and whether the reviewer read the
whole path **(verified)** or reasoned from part of it.

### High

1. **The self-update trusts a digest published beside the package, with no
   signature, and takes Gatekeeper out of the loop.** (verified) The release
   list comes from `api.github.com` (`concat-host/src/updates.rs:45`), the
   package URL and its SHA-256 from `manifest.json` in the same GitHub
   release (`updates.rs:340-383`), written by `scripts/models.py
   release-manifest` in the release job (`.github/workflows/release.yml:100-108`)
   with `contents: write`. The check at `updates.rs:430` proves only that
   the bytes match what the release says they are: whoever can write the
   release (a leaked token, a compromised maintainer account, the release
   action) replaces the package and its digest together, and every person
   who presses Install runs it. On macOS the swapped bundle then has its
   quarantine stripped (`updates.rs:539-541`); the Windows installer is
   unsigned (no `signtool` in `build-app.yml`; Inno with
   `PrivilegesRequired=lowest`, `assets/windows/concat.iss:59`); the macOS
   bundle is notarised only when the secrets are set (`build-app.yml:463-498`).
   The input hygiene around it is good: drafts and pre-releases filtered,
   the tag validated before it enters a URL, a file name with a folder
   refused, no check at start (only when the page opens). A compiled-in
   public key and a signed manifest would close this.

2. **From the window's Remote page a token holder can truncate
   `~/.ssh/authorized_keys`.** (verified) `Config::roots` empty means the
   home folder (`concat-server/src/lib.rs:80-86, 145-149`), and the Remote
   page passes no roots (`concat/src/panes/settings.rs:561-565`).
   `preview.frame` with `output: "~/.ssh/authorized_keys"` (or `~/.zshrc`,
   a keychain, an autostart entry) passes `writable` (`concat-api/src/lib.rs:648`),
   then `create_dir_all` and `File::create` truncate it and fill it with
   PNG bytes (`lib.rs:950-964`); `export.run` does the same for anything
   FFmpeg can name a container for. Not code execution, but silent
   destruction of credentials and shell profiles by anyone with the token.
   Two neighbours: with neither `HOME` nor `USERPROFILE` set the root list
   is empty and `writable` treats empty as unconfined (`lib.rs:244`), the
   opposite of the comment at `concat-server/src/lib.rs:79`; and
   `project.open` takes any readable folder, after which `project.save`
   and the mask cache write into it (`lib.rs:454-456, 576-580`), so an
   existing project on a shared volume can be rewritten from the socket.

3. **Every JSON connection leaks a file descriptor, and unauthenticated
   callers hold the seats.** (verified) `json.rs:106-122` (TCP) and
   `161-177` (Unix) clone the stream into a closure pushed onto
   `connections`; nothing removes it when the connection ends (`json.rs:135`
   shuts the socket, the clone stays) and the list is drained only in
   `Server::shut` (`concat-server/src/lib.rs:284-288`). Any local process,
   token or not, that connects and disconnects 256 times exhausts the
   editor's descriptors: no media opens, no export writes, `accept` spins
   on `continue` (`json.rs:100`). A well-behaved script that connects per
   request leaks the same way. Separately, `Seat::take` runs before the
   handshake (`json.rs:102, 157`), so 64 idle connects refuse the token
   holder with `busy` for each 10 s window, renewably.

4. **Clear cache deletes the media behind reversed and enhanced clips, and
   those copies are never swept.** (verified for reverse) The reversed copy
   lands in `project/cache/reverse-<hash>-<start>-<dur>.mp4`
   (`concat-host/src/reverse.rs:71-93`) and `adopt_reversed` makes it the
   clip's media through `ReplaceClipMedia` (`concat/src/studio.rs:5495-5520`).
   `projects::clear_cache` removes the whole `cache/` folder
   (`projects.rs:330-339`), from Settings (`studio.rs:6202-6216`), so a
   reversed clip is missing media at the next open; the original import is
   untouched but the clip no longer points at it. Enhance copies are named
   into the cache the same way (`enhance.rs:57-76`). A new file is written
   for every different trim (the key holds start and duration), at CRF 16,
   and nothing sweeps them; `proxy::sweep` touches only `cache/proxy/*.mp4`.
   Processed media belongs under `media/`, or the sweep and Clear cache
   have to know what a clip points at.

5. **0.2.4 documents with reversed clips or preset animations open silently
   changed.** (verified) `Clip` lost `reverse` and the four `animation_*`
   fields, `animation.rs` (800 lines) and `SetClipAnimation` went, and
   `MIGRATIONS` is still two steps (`concat-project/src/doc.rs:62-71`).
   `Session::open` surfaces nothing; the retired-effects path gets a
   notice, this does not, and CHANGELOG's "Changes to note" does not say
   it. A 0.2.4 project with a reversed shot opens, previews and exports
   forward with no message; the flag rides in `extra` and is written back
   forever (only a menu arm still reads `"reverse"`).

### Medium

6. **The Remote page's embedded API still opens a second GPU device inside
   the window.** (verified path; the crash itself is #202's) `Api::new`
   builds `Monitor::new()` (`concat-api/src/lib.rs:179`), and an
   `export.run` goes `ExportJob::run` → `export::run` → `run_on(request,
   None, …)` (`concat-host/src/export.rs:89-95`) → `best_compositor()` →
   `WgpuCompositor::new()` (`concat-export/src/lib.rs:1094-1130`); previews
   use the static `headless()` device. The window's own export and cards
   use `monitor.sibling()` (`concat/src/panes/export.rs:353`,
   `studio.rs:6393`). So a remote export or preview on the NVIDIA laptop of
   #202 takes the road the fix closed. The CLI and a headless API rightly
   use their own device or fail with `NO_RENDERER`.

7. **`[[replaces]]` upgrades drop keyframes, are silent, and skip user
   packages and templates.** (verified) `Editor::upgrade_links` rewrites
   links before any edit and outside undo (`concat-project/src/editor.rs:89-107`);
   `Session::open` ignores its `bool` (`session.rs:104-105`): no dirty flag,
   no notice. `Package::replacing` returns `keys: BTreeMap::new()`
   (`concat-effects/src/catalogue.rs:585-591`, admitted at 553-556). An
   animated Green Screen opens as a constant Chroma Key; the file is
   intact until the next save, then the old link and its keys are gone.
   Only `Catalogue::builtin()` is consulted, so a user package's
   `[[replaces]]` never fires; `templates.rs:323` builds an editor without
   the pass. No test covers `upgrade_links`.

8. **HDR proxies are not regenerated for media imported before 0.2.5.**
   (verified in the open path) The HDR flag in the proxy name comes from
   `item.color_space.is_hdr()` (`studio.rs:6123, 2481`, `proxy.rs:72-74`),
   and `MediaItem::color_space` is absent from a document written before it
   existed and reads SDR (`model.rs:171-176`). For an HDR file imported
   under 0.2.4 the old SDR proxy is kept by the sweep, still adopted, and no
   HDR proxy is queued; no re-probe of existing media was found. CHANGELOG
   says the tone-mapped proxies "are made again".

9. **The Hub does heavy work in line, and a panic in any verb leaves a
   zombie server.** (verified) `hub.rs:83-87` has no `catch_unwind`; a
   panic in `dispatch` ends the API thread and every later call returns
   "the server is shutting down" while the listeners keep accepting and
   the Remote page says it is listening. The one thread still composites
   previews, paints titles, runs every `media.probe` and copies template
   files (`concat-api/src/lib.rs:326, 465, 485, 632, 689`,
   `templates.rs:368`). Also: a subscriber whose 256-line outbox fills is
   dropped on the first `false` with no signal (`hub.rs:58-66`,
   `json.rs:319-324`); progress goes out every 15 frames, so a client that
   reads nothing for about a minute never sees `export.done`.

10. **Downgrade is one click with no gate.** (verified) The list keeps
    every stable release from 0.2.5 (`updates.rs:141-143`) and Install runs
    the chosen one (`settings.rs:447-497`, `ui/dialogs/settings.slint:1090-1105`)
    with no "older than this build" check. An older release refuses a
    document only when `DOCUMENT_VERSION` was bumped; a newer document at
    the same version opens with its features silently absent.

11. **The model has no ceiling on frame size or rate.** (verified for the
    model) `SetTimelineVideo` accepts any positive value
    (`commands/timelines.rs:54-57`, `model.rs:1789-1791`); the ceilings live
    in the window (`FRAME_SIDES 16..8192`, `studio.rs:243-246`) and the API
    (`MAX_SIDE`). A hand-edited document with `"width": 100000` opens; the
    compositor's texture limit is 8192 (`concat/src/gpu.rs:89`). §6's
    "clamps live in `Clip::tidy`" has no counterpart for the timeline's
    frame.

12. **Every undo snapshot deep-copies the bin.** (path verified) `editor.rs:141`
    clones the project; `Project.media: Vec<MediaItem>` is not behind `Arc`
    (`model.rs:1812-1813`); `Batch` clones again per nesting level
    (`commands/mod.rs:994`). 200 snapshots of a 2 000-item bin is 400 000
    `MediaItem` copies, against the module doc's "a snapshot copies
    pointers" (`editor.rs:6-10`).

13. **The export is still one thread, and playback's two old costs
    remain.** (verified) Decode → composite with a GPU readback →
    `write_frame` on one thread (`concat-export/src/lib.rs:1204-1330`);
    `ExportClip` has 40 public fields and `BuiltTimeline` 12 side tables
    (`resolve.rs:88-118`). `audio_pieces` still cuts a curved clip into up
    to 400 pieces, each its own decode (`lib.rs:1005-1007`,
    `studio.rs:2124-2136`); the mixer loops every clip per output sample
    (`playback.rs:1032-1055`).

## 7. What is good, and should stay that way

- **The layering, still.** Every arrow points one way; FFmpeg is only in
  concat-media; the CPU compositor is a test oracle and nothing else.
- **`Session::open`'s three-way split** (none, corrupt, newer) with two
  refusal tests (`session.rs:73-100, 341-369`). The critical of the 23rd,
  closed with a test that pins it.
- **`clips_where` + `tidy_touched`.** Sharing preserved by construction and
  one clamp function used both on load and after every command
  (`model.rs:1972`, `editor.rs:170`).
- **`follow_first_hdr` as an editor-level diff.** One undo step for free,
  correct through `Batch`, gesture folding, undo and redo, with a test that
  undo takes the clip and the colour back together (`lib.rs:144-192`).
- **Mandatory digests with pinned upstreams**, one `download`/`verify` pair
  shared by models and the updater (`models.rs:201-310`).
- **The updater's input hygiene.** Drafts and pre-releases filtered, the tag
  validated before it becomes a URL, a file name with a folder refused,
  cancel and timeouts everywhere, and a fallback to "open the package" when
  the swap cannot be done (`updates.rs:119-161, 361-368, 483-511`).
- **`Api::writable` + `resolved`.** Refuse `..`, canonicalise the deepest
  existing ancestor, compare component-wise, with a test that walks a
  not-yet-existing folder (`concat-api/src/lib.rs:243-275, 910-929, 1384-1435`).
- **`OpenProjects`** as a shared, cheap-to-clone register with
  claim-or-name-the-holder semantics and release in `Drop`.
- **`SingleFlight`.** One slot per long job, released on drop even through
  a panic, cancel reaches only the running job (`jobs.rs:18-111`).
- **The lent compositor**, the adapter named in the log at the first frame,
  and an end-to-end test that exports on a sibling device
  (`concat-export/src/lib.rs:1129-1140`, `tests/export.rs:701`).
- **Reverse's two-pass, bounded-memory design** and partial-then-rename
  landing (`reverse.rs:63-65, 167-177, 219-291`).
- **The tolerant `wire` readers**, per-struct `extra` maps and the
  `WRITER_OWNED` list: a hand-edited file degrades instead of failing.
- **One contract, two transports**, a constant-time token with the test
  that pins its promise, and `version.capabilities` extended by the server
  with what is actually listening.
- **A hand-written CHANGELOG** grouped by where the person notices the
  change, and CI that gates on fmt, clippy, perf and wasm on every push.

## 8. Where we stand

The 23 September audit ended with seven recommended steps. Five days later:

| Step (23 Sept) | Landed |
|---|---|
| 1. Correctness trio (open, scheduler, epoch) | open and scheduler yes; epoch exists, coverage to confirm |
| 2. Server limits, root allowlist, shared exporter | yes, with the home folder as the root and two holes (findings 2, 3) |

| 4. Trial at install, error scopes, source-hash keys | trial and error scopes yes; key scheme to confirm |
| 5. `clips_where`, one clamp pass, `start_time`, Darken/Lighten | all four, with the speed range still copied |
| 6. Art refresh on change, sweeps, graph caching | art yes; proxy swept; art, peaks, reverse, enhance not |
| 7. CI matrix, perf gate, release on CI, docs | matrix, perf and release yes; parity and docs partly |

And on top of that list, the HDR plan's phases 0 to 3 shipped: one GPU
compositor in linear light, format 2 packages with probes and multi-pass,
HDR in and out, scopes, and the retirement of the old effects. That is the
week's real story: the picture pipeline is now one thing, and the audit's
render and effects findings of the 23rd (CPU kernels for 147 shaders,
unbounded GPU memory, chains never pixel-compared) are gone with the code
that carried them.

What the week bought in debt is of two kinds. The first is the feature
that shipped fastest: the self-update is well built at every step except
the one that matters, the trust root, and it should not sit in a release
for long without a signature. The second is the seam between old and new:
pre-0.2.5 documents with reversed or animated clips, pre-0.2.5 HDR imports,
and `[[replaces]]` links with keys all open changed and say nothing. Both
are cheap next to what was paid this week.

**Recommended order.** Each line is a day or a few, and each closes a
finding above.

1. Sign the update manifest with a key compiled into the app and refuse an
   unsigned one; keep the quarantine bit; confirm a downgrade; sign the
   Windows installer and notarise every macOS build. (1, 10)
2. Remote page defaults: root the API at the project and export folders,
   not the home folder; refuse to start with no root; check `writable` in
   `project.open` or `save`; count seats after auth; drop the connection
   clone when it ends; `catch_unwind` round the Hub's dispatch; hand the
   embedded API the window's device through `sibling()`. (2, 3, 6, 9)
3. Processed media out of `cache/`: put reverse and enhance copies under
   `media/` (or teach Clear cache and the sweep what clips point at); sweep
   `cache/art` and peaks; re-probe pre-0.2.5 media for its signal at open.
   (4, 8)
4. Tell the person: a migration step for `reverse` and the animations
   (turn the flag into the new Reverse, or name the clips in the open
   notice); surface `upgrade_links` and carry the keys; run it for
   templates and user packages. (5, 7)
5. Finish the 23 September list: an epoch check on every worker path; a
   `tidy` for the timeline's frame; one speed range; the CLI's socket;
   `ui/demo/`; the five ⌘ glyphs; the `mobile.yml` sentence. (11, 15, 18)
6. Pipeline the export (decode, composite, encode on three threads) and
   give the mixer an index; `Arc` the bin in snapshots. (12, 13)
7. Speech, enhance, proxies and CBR as API verbs, so "three ways in" holds
   for everything the window does. (19 of the 23rd)

After those, phase 4 of the HDR plan (a true HDR preview), then phase 5
(zero-copy hardware frames, hardware encoders) in the plan's order.
