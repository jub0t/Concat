# Concat audit, 15 October 2026

Where the codebase stands three days after the 12 October audit. Code read
at `ab21457`, with the two crates PR #361 touched (concat-export, the host's
export tests) read at its merge `11e1bd3`. That is 36 non-merge commits past
the last audit's `c06560e`, with v0.2.7 released in between (13 October,
from `14b5998`). Same method, same 1-10 scales, every carried finding
re-verified against today's lines. Every finding names a file and a line. The sibling
`AUDIT-2026-10-15-QUICK.md` is this audit as a one-screen scorecard, and
`2026-10-15/` holds the four reviewers' own reports.

**How it was done.** Four reviewers each read one part of the tree: the
window (Rust, Slint, locales); host, server, API and CLI; media, render,
export and core; project, effects, text, vision, speech, Android, iOS, CI
and release. Each re-verified the 12 October findings in its part, read
every commit since as a commit (does it do what it says, with what test,
missing what), scored its part and reported new findings. Each reviewer's
counting script reproduced the 12 October table exactly on `c06560e` before
counting today's. The headline items (main's CI, the Android decoder, the
Android launch check, the unsigned Windows release, the Intel Mac crash,
the interface scale, the transition lanes) were then re-read by hand, and
run where a command could show it. `cargo fmt --check`, `cargo clippy
--workspace --all-targets -D warnings`, `cargo test --workspace`,
`scripts/locales.py --check` and `scripts/models.py --check` were run on an
Apple silicon Mac (macOS 26, Metal). The app was not launched, and no phone
or release bundle was built.

**Labels.** *Verified*: read at the line, or run. *Reasoned*: followed
through the code or a dependency's documented behaviour, not reproduced.
*Suspected*: says why.

## The short version

0.2.7 is the first release in which every desktop bundle passed its launch
check, and about 45 000 people downloaded it in two days, 19 000 of them on
Windows and 16 000 on Android. The code that landed since is mostly careful
and mostly tested. None of that is the problem.

The problem is that the project has stopped looking at what it ships:

- **`main` has been red for two days** over one stray file (`vn.json`), and
  because that check runs first, Linux has run no clippy, no tests and no
  effect-package GPU render since 14 October. Six PRs, two of them
  contributor features, were merged on top of red.
- **Android, the second-largest audience, has never been started by CI.**
  The launch check runs an arm64-only APK on x86_64 emulators, gets
  "untestable", and reports success. On the device, video is decoded on the
  CPU while the log says MediaCodec, and the activity probably closes
  itself on a dark-mode switch.
- **iOS ships without Import.** 4 159 people downloaded an editor that
  cannot open a single clip.
- **Windows 0.2.7 is unsigned.** The signing step exits 0 when the
  certificate is missing, so Smart App Control refuses the app (#306, #311)
  on the platform with the most users.
- **The Intel Mac build does not start on macOS 12 to 13.2**, which it
  declares as supported (#333).
- **Phones have not been built since v0.2.7.** The phone workflow fails on
  every contributor PR with "workflow file issue", and both hand-started
  runs on `main` failed.

Of roughly 80 findings carried from the last two audits, one was fixed
outright (the release notes' previous tag), about five partly, about seven
got worse, and the rest are unchanged. None of the 11 October server items
has landed.

Most of the fixes are small. Deleting `vn.json` turns `main` green.
Failing the tag build without a certificate is three lines. The Android
recreation fix is one manifest attribute. The order is in section 8.

## 6. New findings, by severity

### High

**H1. `main` has been red for two days, Linux has run nothing, and features were merged on top.** *Verified by running and in CI.*
- `src/crates/concat/locales/vn.json` is a second, stale Vietnamese file
  (from PR #304, merged as `f064b68`). It is not in `BUILT_IN`
  (`i18n.rs:57-83`), which ships `vi`, and it is 11 keys behind.
- `locales.py --check` exits 1 on it at `ci.yml:141`, which runs before
  clippy (`:150`) and the tests (`:168`). Linux is CI's only place where
  the 125 effect packages render (lavapipe); Windows skips them and macOS
  only compiles. So no effect-package GPU run, Linux test or clippy has
  happened since 14 October.
- On Windows the same test fails (`i18n.rs:344`), and fc7e6a9's
  `consolidation_preserves_the_timeline_clock_of_animated_effects` hits
  the 300 s timeout on WARP because it lacks the `heavy_gpu` guard.
- Merged on red since: #329, #336, #357 (fc7e6a9), #359, a68641c, 5add799,
  #361. Three of them edited `vn.json` without noticing it is never
  compiled in.
- **Fix:** delete `vn.json`; guard the consolidation test; make "green
  before merge" a rule. Five minutes.

**H2. Windows 0.2.7 shipped unsigned, and nothing stops the next one.** *Verified.*
- `build-app.yml:946-949`: when `WINDOWS_CERTIFICATE_PFX` is unset the step
  prints "No signing certificate: the build is unsigned." and exits 0, on
  a release tag too. The v0.2.7 log has that line.
- Smart App Control refuses unsigned DLLs (#306, #311, both open), and
  SmartScreen warns everyone else, on the platform with 19 000 of the
  downloads.
- **Fix:** fail a tag build without the certificate, or say "unsigned" in
  the notes until there is one.

**H3. iOS ships without Import.** *Verified.*
- `platform.rs:675-694` only logs "no file picker on this platform yet";
  the only `install_file_picker` call is Android's
  (`concat-android/src/lib.rs:223`). Nothing on iOS installs a picker or
  an export publisher.
- `src/scripts/ios-app.sh` still lacks `UIFileSharingEnabled` and
  `LSSupportsOpeningDocumentsInPlace`, so the Files app cannot see the
  app's folder either. There is no way to get a clip in.
- 4 159 downloads of the 0.2.7 `.ipa`; #332 confirms it. The README marks
  iOS ✅.

**H4. The Android launch check has never run the app, and it gates releases as passed.** *Verified.*
- The emulators are x86_64 (`mobile.yml:301`), the APK is arm64-only, and
  ARM translation crashes ONNX Runtime's static initialiser. Every Android
  smoke (rc.3, rc.4, v0.2.7) ended in `untestable_here`
  (`smoke-android.sh:241-277`) with exit 0. The API 30 matcher accepts any
  SIGSEGV at 0x8 before the app's first line (`:262-266`).
- `mobile.yml:33` says "No phone build passes unless it starts on a
  phone". For Android that is false. The "started on a real phone by hand"
  step has no record anywhere.
- So the 16 001 Android downloads, #312 (Android 11) and #286 (export) were
  never checked by CI.
- **Fix:** build an x86_64 APK from the same source for the emulator, or
  use a device farm.

**H5. Android probably closes itself whenever the activity is recreated.** *Suspected, reasoned from android-activity 0.6.1 and Slint.*
- `concat-android/Cargo.toml:66` declares only
  `orientation|keyboardHidden|screenSize`. A dark-mode switch (including a
  scheduled one at sunset), split screen, a display-size, font-scale or
  locale change recreates the NativeActivity, and android-activity calls
  `android_main` again in the same process.
- On that second call `set_var` runs while worker threads are alive
  (`lib.rs:31-39`), `slint::android::init` fails because the platform is
  already set, and `return` (`:388-391`) finishes the activity.
- The app vanishes mid-edit with no message.
- **Fix:** add `uiMode|screenLayout|smallestScreenSize|density|fontScale|locale|layoutDirection`
  to `config_changes`, and guard a second `android_main`.

**H6. Intel Mac 0.2.7 does not start on macOS 12.0 to 13.2.** *Verified in the field (#333, #342).*
- dyld: `Symbol not found __ZNSt3__18to_charsEPcS0_d` from
  `libonnxruntime.1.23.2.dylib`. That libc++ symbol exists from macOS 13.3.
- The bundle declares 12.0 (`build-app.yml:102`, `LSMinimumSystemVersion`
  at `:582`) and links the runtime at load (`:294-302`,
  `ORT_PREFER_DYNAMIC_LINK=1`). The launch check runs on `macos-15-intel`
  only, so it cannot see this.
- **Fix:** load ONNX Runtime lazily (`ort` `load-dynamic`) or raise the
  minimum to 13.3; add an `otool -l` minimum-OS check over every bundled
  dylib.

**N1. Android never decodes on MediaCodec; every phone clip is decoded on the CPU.** *Verified by reading; the FFmpeg behaviour reasoned from its decoder tables.*
- `Device::attach` looks up the hardware config on
  `decoder::find(context.id())` (`concat-media/src/hardware.rs:305-306`),
  FFmpeg's built-in decoder, and `open_codec` opens that same decoder
  (`decode.rs:741-743`). FFmpeg's built-in `h264` and `hevc` decoders list
  DXVA, D3D11, NVDEC, VAAPI, VDPAU, VideoToolbox and Vulkan, never
  MediaCodec, which exists only as the separate `*_mediacodec` decoders.
  Only the encoder side ever names those (`encode.rs:108-110`).
- Meanwhile `hardware_wins` says "MediaCodec takes everything"
  (`hardware.rs:198-202`), and the log says "video decode on MediaCodec"
  (`:358`).
- A phone's own 4K HEVC and 10-bit HDR footage is decoded on the CPU for
  playback, scrubbing, filmstrips and export: stutter, heat and battery,
  with up to 8 warm readers (`pool.rs:568-593`), each with frame threads on
  every core (`decode.rs:731-735`), on 4 GB phones.
- **Fix:** open `h264_mediacodec` / `hevc_mediacodec` by name, and first
  fix N9's dropped packet on "try again", which those decoders will hit.

**N2. A chain of transitions climbs into the next track's lane.** *Verified by reading.*
- `overlap` reads the outgoing clip's lane at the moment it resolves and
  puts the incoming clip one lane above (`concat-export/src/lib.rs:806,
  816`). With A→B→C on track t (lane 2t), B goes to 2t+1 and C to 2t+2,
  which is track t+1's lane, for C's whole length. A fourth clip goes to
  2t+3.
- One clip per lane is drawn (`concat-core/src/timeline.rs:472-480`), so
  wherever C overlaps a title, caption or overlay on the track above, one
  of them is not drawn. The monitor resolves the same way
  (`lib.rs:2194-2195`), so the person sees it and cannot fix it.
- The typical case is a slideshow with cross-fades and auto-captions. It
  predates #361; #361's fades make chains more likely. No test covers two
  transitions in a row.

**N3. Importing a large HDR clip opens NVENC in the background.** *Verified.* This makes 12 October's #9 worse.
- Every video larger than HD gets a proxy (`concat/src/studio.rs:3005-3032`).
  For HLG or PQ sources it is HEVC with `hardware: hdr`
  (`concat-host/src/proxy.rs:224-243`), so on Windows and Linux it opens
  `hevc_nvenc` first (`encode.rs:117-130`).
- On the hybrid-GPU laptops of #309, adding a phone's 4K HDR clip to a
  project can segfault the app in libcuda, with unsaved edits, without
  any export. On Android the proxy fails outright (ten-bit filtering
  removes MediaCodec, `encode.rs:551-561`), so those clips never get one.
- The only escape, `CONCAT_HARDWARE_ENCODE=0`, is not mentioned anywhere
  a user would see it. HDR merges take the same path (L4).

**N4. No phone has been built since v0.2.7.** *Verified via `gh`.*
- `mobile.yml:53-77` has no push trigger. On pull requests it dies with
  "workflow file issue" and runs no job (fc7e6a9, a68641c, 7cb4494, #361).
  The last two hand-started runs on `main` failed.
- So the scale handler's `cfg`s, the phone "Apply to all" sheet, the
  progress repaint, the merge code and #361 have never been compiled for
  the platforms with the most broken experience.

### Medium

**M1. "Interface scale" replaces the display's scale instead of multiplying it.** *Verified against Slint 1.18.1's source.*
- `prefs.rs:147-149` turns the percentage into `percent / 100`, and
  `lib.rs:169-183, 1496-1507` sets it as `SLINT_SCALE_FACTOR`, which
  Slint's winit backend takes as the absolute factor
  (`winitwindowadapter.rs:602-608`) and which suppresses the monitor's own
  scale-change event while set (`:1544`).
- On a Windows laptop at 150 %, "100 %" and "125 %" make the interface
  smaller. On a Retina Mac, "100 %" halves it. The hint (`en.json:416`)
  says "larger than the display's own scale". Moving the window to another
  monitor no longer rescales.
- **Fix:** multiply by the window's scale factor and re-apply on the
  scale-change event. Before the next release.

**M2. The export sheet can show a codec it will not use.** *Verified.* `dialogs/export.slint:392-403` passes no `disabled` list, `select.slint:125-128` assigns its own value, and `panes/export.rs:171-176` refuses a codec the device cannot encode. Pick AV1 without an AV1 encoder (most Android phones, many Windows machines): the picker reads AV1, the file is H.264. Present since 28 September.

**M3. On phones, dialogs and toasts ignore the safe area.** *Code verified; on-device effect reasoned.* Only the main layout is inset (`app.slint:594-597`). Modals sit at the window root (`app.slint:677-906`, `modal.slint:48-57`) and toasts 16 px above the bottom edge (`toast.slint:86-88`). On edge-to-edge Android (targetSdk 35) and iPhone, failure toasts sit under the navigation bar or home indicator, and a tall sheet's close button under the status bar. #328, #353.

**M4. Duplicate takes two undo steps, and the first leaves the whole source file on the timeline.** *Verified.* `duplicate` (`studio.rs:6885-6890`) calls `place_copy(..., None)`, which applies `AddClip` (the whole file at the lane's end) and the shaping batch as separate steps (`:6986-7040`). Ctrl+Z after duplicating 3 seconds of a 2-hour file leaves a 2-hour clip at the end of the lane. Pass a gesture, as Paste does.

**M5. Merge now re-encodes where it used to rejoin losslessly.** *Verified.* fc7e6a9 dropped the window's `MergeClips` path. `merge()` (`studio/consolidate.rs:71-200`) renders the selection to `media/merged-*/merged.mp4` at CRF 16 (`concat-host/src/consolidate.rs:118-131`). Rejoining two halves of a split clip costs a render and a generation of quality. Progress shows only in the tray button's label; refusals are English in every language (`consolidate.rs:49-52`). Keep the lossless join when it applies.

**M6. Any local process can exhaust the window's file descriptors through the Remote API, without a token.** *Verified.* Every connection, authenticated or not, leaves a duplicated socket in `connections` until `stop` (`concat-server/src/json.rs:109-122, 164-177`), and the seat is taken before the handshake (`:102, :157`). A few hundred connections (256 on macOS, 1 024 on Linux) and saves fail with "Too many open files" (`concat-host/src/projects.rs:186-187`), decoders fail, and the accept loop spins at 100 % (`:100, :156`). A script that connects once per call gets there in normal use. Off by default.

**M7. The audio mix holds every later clip's decoded sound, and Cancel is ignored while it runs.** *Reasoned.* `mix_to_file` opens every piece at once (`concat-media/src/audio.rs:405-470`) and feeds them round-robin (`:638-685`); a clip's `adelay` releases nothing until the mix reaches its start, so decoded audio piles up: about 1.4 GB per hour of back-to-back clips at 48 kHz stereo float. On a phone that is an out-of-memory kill. A speed-curved clip adds up to 400 inputs (`concat-export/src/lib.rs:1234`). Cancel is checked only before and after (`:1130-1136`).

**M8. Transitions crossfade sound in the file, not in the window.** *Verified.* Playback audio comes from `flattened_clips()` (`studio.rs:2663`, `concat-host/src/session.rs:301-307`), which never passes through `resolve_transitions`. The export fades both sides and, since #361, plays the outgoing clip's sound past its out-point. The editor plays a hard cut; the file has a crossfade and source audio nobody heard while editing.

**M9. FFmpeg's own error lines are thrown away.** *Verified.* The log relay keeps only FATAL and PANIC (`concat-media/src/ffi.rs:44-56, 101-105`). When MediaCodec, NVENC or x264 refuses to open, the log gets "{name} would not open ...: Invalid argument" (`encode.rs:1163`). On the platform where export has never been seen working (#286), the line that explains why is dropped.

**M10. Android import can crash after a process kill or on a provider error.** *Suspected.* `ConcatFiles` is a Fragment loaded from an in-memory dex (`concat-android/src/lib.rs:154-195`) and added for the pick (`ConcatFiles.java:146-150`). If Android kills the process while Photos or Drive is in front (common on 3-4 GB phones), restoring the activity cannot find the class: a crash on return, and the pick is lost. `copy()` catches only `IOException` (`:262-289`), so a `SecurityException` from a revoked grant kills the app.

**M11. Android projects and imports are deleted on uninstall, and users cannot reach them.** *Verified.* `HOME` is `external_data_path` (`lib.rs:37-38`) and every pick is copied into `getExternalFilesDir/Imported` (`ConcatFiles.java:203-204`). On Android 11 and later `Android/data` is hidden from file managers. A reinstall deletes every project, and every import doubles its storage.

**M12. The Android export sheet opens up to three MediaCodec encoders on the UI thread at start.** *Path verified, cost suspected.* `panes/export.rs:631-633` calls `encodable()` for H.264, HEVC and AV1 at the first publish; each opens a real 720p encoder (`encode.rs:170-180, 472-500`). A slow vendor codec delays start; one that hangs heads for an ANR.

**M13. The crash handler takes locks and can allocate, despite its doc.** *Reasoned from the loaders' documented locking.* `dladdr` (`concat-host/src/crash.rs:217`) takes the loader's lock (glibc, bionic and dyld alike); `to_string_lossy` (`:218`) can allocate; on Windows `std::thread::current()` (`:398`) allocates on threads Rust did not start and aborts after TLS teardown, and `GetModuleFileNameW` (`:442`) takes the loader lock. A crash while another thread loads a library, which is exactly #326's start-up window, can hang with nothing logged. Write the raw code and PC first; record module ranges at install.

**M14. On Vulkan, which includes Android, every export, merge and card round opens a second GPU device.** *Path verified, impact suspected.* 14b5998 (titled "linux") makes `Monitor::off_thread` (`concat-host/src/preview.rs:146-153`) return none on Vulkan, and Android picks Vulkan (`concat/src/gpu.rs:52-57`). The cards build a new compositor every round (`cards.rs:404-407`). On 3-4 GB phones and the #312-class drivers, that is a second device's memory and pipeline compiles. It is also the second-device road #202 found deadly on Windows NVIDIA laptops, now untested on Linux NVIDIA.

**M15. Release notes told Windows users a false thing.** The 0.2.7 notes say "a blur or a glow no longer stalls an export" (be1b882), which was reverted. Published, never corrected. Four more CI-internal lines went out with them.

**M16. The README promises a gRPC API and a CLI that no download ships.** *Verified.* Releases build only `-p concat` (`build-app.yml:523`) without the `grpc` feature (`concat/Cargo.toml:133-134`), and no `concat-cli` is published. The window serves JSON-RPC over TCP only.

### Low

- **L1.** Runtime `set_var` with a false SAFETY claim (`concat/src/lib.rs:1498-1507`) while decoder, audio and export threads run; on Linux, FFmpeg, libva and Mesa call `getenv` on those threads. Choosing "System" also removes a hand-set value.
- **L2.** Merge's checks run on every lanes publish, every playback tick and drag move (`studio.rs:8010-8015`), cloning every selected clip (`clips.rs:905-912`); `selected` per visible clip is O(visible × selected) (`studio.rs:7843`).
- **L3.** The progress bar repaints the whole window every frame while a job runs (`primitives/modal.slint:333-338, 373`), competing with whisper for CPU and battery on a phone.
- **L4.** "Apply caption style to all" is silent when nothing changes (`studio.rs:5000-5017`), strips the receiving titles' position keys (`:1373-1379`), and shows when the title is alone on its lane.
- **L5.** Merged renders are never collected: undo keeps `media/merged-*`, and Clear cache spares `media/`. An HDR merge goes through the NVENC-first path.
- **L6.** Captions: no run id on progress or finish (`panes/captions.rs:161-170`), so a cancelled run's late "cancelled" can close the reopened sheet (suspected).
- **L7.** ClearType (`bdcaedf`) ships LCD text on the most-used platform without anyone having looked at it on a Windows screen.
- **L8.** `EffectClock` does not forward `lost()` or `deliver_hdr()` (`concat-export/src/lib.rs:1734-1770`). Latent.
- **L9.** Decoders drop a packet on "try again" (`decode.rs:895-897`, `audio.rs:372-374`, `samples.rs:276-278`). Harmless now; corrupts pictures as soon as N1 is fixed.
- **L10.** About 45 MB (8-bit) or 80 MB (HDR) allocated per exported 4K frame (`gpu.rs:3352-3380`, `encode.rs:1489-1508`).
- **L11.** API `ConsolidateClips` adopts any file whose duration covers the span (`commands/clips.rs:612-645`), with no verb that renders a selection.
- **L12.** Weak Remote API tokens accepted (`settings.rs:575`), no auth throttle (`json.rs:267-291`), `0.0.0.0` binds allowed. On a LAN, a short token can be brute-forced into writes anywhere under home.
- **L13.** Two crash codes in the table can never arrive: fail-fast skips the filter (`crash.rs:358-359`).
- **L14.** A one-channel output device loses the right channel (`playback.rs:1172-1175`); the audio callback frees memory on the real-time thread (`:1107`).
- **L15.** Model and update downloads have no size limit (`concat-host/src/models.rs:258-276`).
- **L16.** `concat.light-leak-flash/effect.wgsl:17` calls `pow` with a negative base, undefined in WGSL, HLSL and MSL (suspected NaN band on some drivers). Write `d*d`.
- **L17.** No top-level `permissions:` in `ci.yml`, `mobile.yml` or `build-app.yml`.
- **L18.** The `v0.2.7` tag was re-pointed after a cancelled run, and tagged while its commit's CI was still running.
- **L19.** No offline shader portability check: naga is used only with `wgsl-in`; `hlsl-out` and `glsl-out` over every package would prove D3D12 and GLES on every runner without a GPU.
- **L20.** Contributor PRs copy English into every locale (3479407: 3 keys, fc7e6a9: 10, a68641c: 2), and missing keys still pass `--check` (`scripts/locales.py:193-194`).

## 7. What is good, and should stay that way

- **The crash line is designed properly**: stack formatting, a duplicated
  descriptor so it never touches the logger's lock, chained to the
  previous handler so tombstones and Windows Error Reporting are
  unchanged, installed before `--version`, and tested by crashing a child
  process on all three desktop runners.
- **`ConsolidateClips` refuses rather than loses**: it checks the frame
  grid, edge transitions, content underneath, detached audio and the whole
  selection; re-checks inputs before adopting the render; is one undo
  step; and is tested end to end through a reopened project. The best-tested
  work of the period, from a contributor.
- **447570a is the right fix built properly**: `patiently` and `until_ended`
  are pure and tested with fakes, and a stall becomes a stated error, not
  a short file.
- **#361 is careful**: half on each side of the cut, keys kept at their
  instants, a held frame when there is no footage, and every replaced test
  rewritten for the new rule.
- **The iOS simulator smoke is real**: exit status checked, the app watched
  for 60 s, its first log line required.
- **Every action is pinned by SHA; desktop downloads and models are
  digest-pinned and fail closed.**
- **The locales are honest**: 673 keys, every placeholder matching, effect
  names out by design.
- **The core held still**: no churn in concat-core or concat-render, and
  the GPU parity suite against the CPU reference is intact.
- **Non-test unwraps: 68 in 93k lines.** 4 of them in the window's 25k.

## 8. Where we stand, and what to do in what order

The engine is in better shape than the product around it. The fixes that
matter most this week are small, and most are in CI and packaging, not in
the engine.

1. **Make `main` green.** Delete `vn.json` (`vi.json` ships). Add the
   `heavy_gpu` guard to the consolidation test. Then stop merging on red,
   contributors included. *Minutes.* (H1)
2. **Pin the runners before 19 October.** Replace `ubuntu-latest` with
   `ubuntu-24.04` in the seven places listed in section 5. *Minutes.*
3. **Stop the Android activity from closing.** Add the missing
   `config_changes` and guard a second `android_main`. *An hour.* (H5)
4. **Fail a release without a Windows certificate**, and get one. Until
   then, say "unsigned" in the notes. (H2)
5. **Make the Android launch check real**: an x86_64 APK for the emulator,
   or a device farm. Until then, say "not tested" in the release, not
   green. (H4)
6. **Fix the interface scale** to multiply the display's scale, before it
   ships in a release. (M1)
7. **Intel Mac**: load ONNX Runtime lazily or raise the minimum to 13.3,
   and add the `otool` minimum-OS check. Tell #333's reporters. (H6)
8. **Android hardware decode**: open the `*_mediacodec` decoders by name,
   after fixing the dropped packet on "try again". (N1, L9)
9. **iOS Import**: a document picker and the two plist keys. Until then,
   mark iOS 🚧 in the README, not ✅. (H3)
10. **Fix the phone workflow** so it runs on PRs and on `main`. (N4)
11. **Transitions**: assign overlap lanes from the original track, not
    the already-moved one, with a test for three clips in a row. (N2)
12. **Hardware encode default**: no NVENC first for proxies, or detect
    hybrid GPUs; surface `CONCAT_HARDWARE_ENCODE`. (N3)

    CLI from the README until a download ships them. (M15, M16)

After that, the medium list in order of who it hurts: the safe area (M3),
the codec picker (M2), Duplicate's undo (M4), the lossless join (M5), the
Remote API fd leak (M6), the audio mix (M7).

## 9. Caveats

- The app was not launched, and no phone or release bundle was built here.
  Everything about phones is from code, CI logs and issue reports.
- "Suspected" findings (H5, M10, M12, M14, L6, L16) are reasoned from
  code and dependency behaviour, not reproduced. H5 is the one most
  worth confirming first, on a real phone, by switching dark mode.
- N1 is verified in Concat's code; the claim that FFmpeg's built-in
  decoders never offer MediaCodec is from FFmpeg's decoder tables, not
  from a run on a phone. A log line from a phone during playback would
  settle it.
- Counts follow the 12 October method, which each reviewer reproduced
  exactly on `c06560e`. Line numbers are at `ab21457`, except
  concat-export and `concat-host/tests/export.rs`, which are at `11e1bd3`.

  #361 was merged (`11e1bd3`), LICENSE-EXCEPTIONS was dropped (`9a528c5`)
  and `docs/merging-clips.md` was deleted (`792b925`). None of those
