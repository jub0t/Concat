# Concat audit, 12 October 2026

Where the codebase stands one day after the 11 October audit, at
`c06560e` (12 October), 39 commits past the last audit's `7223d64` and
110 past the 0.2.6 tag, with two release candidates (`v0.2.7-rc.1`,
`v0.2.7-rc.2`) tagged and failed in between. Same method, same scales,
every finding from the 11th (and what it carried from the 9th, 4th and
28th) re-verified against today's tree. Every finding names a file and a
line. The sibling `AUDIT-2026-10-12-QUICK.md` is this audit as a
one-screen scorecard.

**How it was done.** Four reviewers each read one part of the tree: the
window's Rust, Slint and locales; host, server, API and CLI; media,
render, export and core; project, effects, text, vision, speech, Android,
CI, release and docs. Each re-verified the 11 October findings in its part
against today's lines, read the commits since the audit as commits (does
each do what its message says, with what test, missing what), scored its
part and reported new findings with locations. The headline items (the
release notes' previous tag, the iPhone's Import, the pool's 24 held
stills, the shared save scratch, the hard-coded hardware encode, the
locale check's missing keys, the auto-closed issues) were re-read by hand,
and where a command could show it, run. Line, test and `unsafe` tallies
use the 11th's counting (Rust lines are `src/` only, without `build.rs`
and `tests/` directories; the bracket is the count outside test modules),
which the reviewers reproduced exactly on the 11th's tree before counting
today's. `cargo fmt --check`, `cargo clippy --workspace --all-targets`,
`cargo test --workspace --no-fail-fast`, `scripts/locales.py --check` and
`scripts/models.py --check` were run on this machine (an Apple silicon
Mac, macOS 26, Metal) today. The app itself was not launched; no phone or
release bundle was built here.

**The working tree is not clean.** Uncommitted on this machine and
intended for 0.2.7: a send-and-receive retry for encoders that answer
"try again" (`concat-media/src/encode.rs`, aimed at Android's MediaCodec,
#286), Android-emulator and iOS-simulator launch checks
(`scripts/ci/smoke-android.sh`, `smoke-ios.sh`, +197 lines of
`mobile.yml`), and an error exit when the event loop fails
(`concat/src/lib.rs`). This audit scores `HEAD`; section 6 reviews the
uncommitted work separately, because it gates the release once
committed. The test run below includes it.

**What the 39 commits are.** All on 11 and 12 October; 33 by the
maintainer, 6 by three contributors (Bengali, Vietnamese, `--project` on
launch). In groups:

- *The release pipeline* (d118484, b161c1d, 2d3a43e, c06560e): every
  bundle launched before upload (`--version`, `--smoke`, an emulated Ivy
  Bridge, an instruction scan), every download pinned by digest, every
  action by SHA, nextest with per-test timeouts, draft releases, Windows
  signing by thumbprint; then the fixes the two release candidates found.
- *Windows* (be1b882, 3178b78, 0a61b65): DXC in, then out the same day;
  the GPU suites that took minutes on WARP skip there; no Microsoft Store;
  the installer in the app's languages. `main` is green because of these.
- *Bugs from the tracker* (132f68d, 34fe37a, 590e483, f1ccdfe, 049823f,
  e5d8197, e1b64a4, b4adc57, 50c18ee): iPhone projects, settings and logs
  (#299); a second Untitled project (#151); a click that moved a clip
  (#247); Detach that said nothing (#310); no sound band on a silent file
  (#283); the last three dialogs off the studio borrow; the inspector's
  section strip (#250) and a title's words field (#139); titles painted
  once (#261); Chatterbox read again on the CPU (#291); an export the GPU
  stops answering ends, and a phone's GPU draws within its limits (#297,
  #312); no hardware encoder opened at launch (#309); a dropdown scrolls
  under a finger.
- *Features* (2d3e651, 5982dc7, 45c061f): Generate captions on a clip's
  menu and a "Use voice from timeline" switch (#302); `--project` on launch.
- *Languages* (30a1742, ad59b61, c65295b, 8a628c6, c0c8827, fa51932,
  5c60bfd, 9737836): 14 languages to 25, a README in each, five new Noto
  fallback faces with a glyph test per locale, a locale check that prints
  on Windows and counts English.
- *Housekeeping* (1d22c12, 7c5cb3d, 0714fb8, 4affa32, 2d27766, af62333,
  91a6df0, the 11 October audit itself): the CHANGELOG, concat-perf and the
  web build removed; AGPL-only licence text; a code-signing policy; the
  version bumped to 0.2.7.

**Scale.** 0 to 10. 8 and up means "keep doing this"; 5 to 7 means
"works, with known debt"; 4 and under means "will bite at the next order
of magnitude, or already bites".

## 6. New findings, by severity

Numbers are this audit's. Each names where to look.

### High

**1. The final 0.2.7 release would ship three lines of notes.** The
release finds the previous tag with `git describe --tags --abbrev=0
--match 'v*' "$tag^"` (`.github/workflows/release.yml:170`), and the two
release candidates match `v*`. Run here, it answers `v0.2.7-rc.2`, and
`release-notes.sh v0.2.7-rc.2 HEAD 0.2.7` prints three lines (the `_exit`
fix, the Windows smoke split, the captions switch); from `v0.2.6` it
prints 82. With `CHANGELOG.md` gone (1d22c12) nothing else carries
0.2.6 to 0.2.7, and the draft (`:179`) catches it only if someone reads
it. Add `--exclude 'v*-*'` when the tag has no hyphen (run here, that
answers `v0.2.6`). (verified by running)

**2. On an iPhone, Import does nothing and says nothing.** The phone's
Import (`phone/editor.slint:850-854`) and Import Font (`:1103`) reach
`platform::pick_files_async`, which on a phone asks `FILE_PICKER`
(`platform.rs:686-692`); only `concat-android/src/lib.rs:223` ever
installs one, so on iOS the answer is `log::warn!("no file picker on this
platform yet")` and nothing on screen. 34fe37a and 132f68d made an iPhone
able to save settings and create a project; without import it cannot
edit anything. Export is the same shape: no publisher on iOS
(`platform.rs:629-635`), so a finished file stays in the sandbox (and
finding 12). Install a `UIDocumentPickerViewController` picker; until
then, `notify` instead of logging. (verified)

**3. Phones are never built on a push to `main`, and the new phone checks
have never run.** `mobile.yml`'s triggers are `workflow_call`,
`pull_request` and `workflow_dispatch` (`HEAD:.github/workflows/
mobile.yml:4, 26-27`); all work lands on `main` directly, so an Android
or iOS break shows only on a contributor's PR, a hand-started run or a
tag. The uncommitted emulator and simulator checks inherit this, and once
committed they gate `publish` (`release.yml`'s `publish` needs `phones`),
so their first run would be rc.3. Run `mobile.yml` by hand on `main`
before tagging; add `push: branches: [main]`. (verified)

**4. On Windows, a blur or glow export can sit for minutes compiling
shaders, and no test watches it.** With DXC reverted (3178b78), D3D12
compiles through FXC, which be1b882's own message says takes minutes over
the blur and glow loops (#297, open). Pipeline creation is CPU work
(`gpu.rs:2497-2558`), so `DEVICE_WAIT` does not bound it; cancel is read
at the top of each frame (`concat-export/src/lib.rs:1381`) and progress
after one (`:1551-1554`), so Cancel does nothing until the compile ends.
It repeats on every export: the window lends `monitor.sibling()`
(`panes/export.rs:516`), whose `drawing_in` starts an empty `shaders` map
(`gpu.rs:836-846, 1291`), so every effect the monitor compiled is compiled
again. And CI no longer sees it: the suites that took past five minutes
on WARP now return early and count as passed (740 run, 740 passed, run
38302292964), their "skipping" lines swallowed by `store-success-output =
false` (`nextest.toml:31`). Windows is the platform with the most
downloads. Share compiled pipelines between siblings; check cancel between
pipeline builds and show a "preparing effects" stage; make a skip visible
in the step summary; run the full suites on a schedule with
`CONCAT_REQUIRE_GPU=1`; say in the 0.2.7 notes that the compile cost
remains. (verified against the runs and the code; the minutes are from
#297 and be1b882's message)

### Medium

**5. More than 24 titles drop out of the monitor during a drag, and every
title is re-treated each frame.** While a gesture is live
(`begin_echo`, `studio.rs:2474`) the monitor paints every title live and
hands each to `monitor.hold_still` (`studio.rs:2600-2618` →
`preview.rs:152-154` → `pool.rs:628-652`); the pool keeps held stills
FIFO, capped at `STILLS_HELD = 24` (`pool.rs:541, 634-638`). Each pass
re-inserts in clip order, so only the last 24 survive; a title not held is
looked for as a file at `memory://titles/…`, fails, and is dropped without
a word (`concat-export/src/lib.rs:1913-1945`). Auto-captions add clips in
time order, so on a captioned timeline the early captions vanish while
anything is dragged, including a caption whose own size is being dragged.
And `hold_still` calls `forget` for every title every pass (`pool.rs:640,
675-685`), even for the same `Arc`, so each is treated again: the
gesture half of #261 is undone. Hold only the titles the plan at the
playhead covers, or stamp held stills per pass as `LivePaintings` does;
skip `forget` when the frame is the same. (verified by reading)

**6. Two saves of one project write the same scratch file.**
`projects::save` always writes `concat.json.saving` (`concat-host/src/
projects.rs:174`) and renames it. The window saves on a pool of three
workers (`concat/src/host.rs:146-190`; `studio.rs:2500-2518`) and
`close_project` saves on the UI thread (`studio.rs:7230-7235`): Ctrl+S
twice, Ctrl+S during an autosave, or a close during a save puts two
writers on one path. Interleaved writes can rename a manifest that does
not parse ("not a Concat project", `projects.rs:224-226`); the loser's
rename fails and toasts "could not save", and a close aborts. Take a
per-path lock, give each save its own scratch name, and skip a save older
than the one on disk. (mechanism verified; the corrupting interleaving
reasoned)

**7. On OpenGL ES, the 30-second device wait is about 2.15 seconds.**
`wait()` passes `Some(DEVICE_WAIT)` (`gpu.rs:1311-1318`); wgpu-hal's GLES
backend clamps it to `u32` and then `i32::MAX` nanoseconds
(`wgpu-hal-30.0.1/src/gles/device.rs:1757-1764`, `gles/fence.rs:
159-163`). On a GLES phone, the #312 device, a frame slower than that
fails `read_back`, kills the compositor, is retried on a fresh device,
asks for a software adapter a phone does not have, and ends the export as
a lost GPU (`concat-export/src/lib.rs:1245-1247`). Not a regression (the
old indefinite wait was capped the same way), but the doc
(`gpu.rs:183-191`) is wrong on the platform it was written for. Loop
short waits until `DEVICE_WAIT` has passed. (reasoned from wgpu's source)

**8. The captions sheet can transcribe a clip other than the one it
shows.** `Select`, `SegmentedControl` and `Switch` assign their own value
(`select.slint:127`, `segmented-control.slint:43`,
`inspector/controls.slint:559`), which in Slint drops the parent's
binding. The sheet binds Switch `checked: root.from-voice`
(`captions.slint:109`), Audio (`:123`), Model (`:134`), Placement (`:207`)
and Size (`:216`) that way, is only hidden when closed
(`modal.slint:34`), and Rust resets the fields on every open
(`captions.rs:201-221`). So: Generate captions on clip A, pick B in
Audio, close, Generate captions on clip C: the list shows B, Rust
transcribes C. Placement and size have shown stale values since before
this week. 590e483 and f1ccdfe fixed this class at two sites a day
earlier; about 33 such bindings remain in `ui/`. Make the three
primitives controlled (emit, never assign), which fixes every site at
once; the sheet's own script box shows the pattern (`captions.slint:
72-86`). (verified in code; the behaviour reasoned)

(`encode.rs:171-180, 442-479`, with tests), but the export always asks for
hardware (`hardware: true`, `concat-export/src/lib.rs:1354`;

## 7. The uncommitted work, before it is committed

Reviewed on the working tree, because once committed it is in the
release.

**The encoder retry (`concat-media/src/encode.rs`).** Right by FFmpeg's
contract: on "try again", read the packets waiting and send the same
frame again (`patiently`, `send`), for the frame and for the end of the
stream; software encoders never answer it, so the desktop is unchanged;
`written` still counts only sent frames; a stall leaves no file, because
the scratch is removed and the output never touched. A good pure test
with a fake. Before committing:
- The old line `/// Writes every packet the encoder has ready.` now heads
  `send`'s doc, and `drain` has none. Move it back.
- After the end of the stream, `drain` still stops at the first "try
  again" (`encode.rs:1341` in the tree). The contract says it cannot
  happen there; this change exists because MediaCodec's wrapper breaks the
  contract on the sending side, and if it does on the receiving side the
  tail of every phone export is lost with no error. Make the final drain
  patient too, in the same commit.
- "Refs #286", not "Fixes": #286 says only "missing codecs", and no
  export has been seen working on a phone.
- The Android launch check never exports. A one-second 720p H.264 export
  in it would exercise `h264_mediacodec` on the emulator's
  `c2.android.avc.encoder`.

**The phone launch checks (`mobile.yml`, `smoke-android.sh`,
`smoke-ios.sh`).** Well designed: Android's fatal lines are matched only
for the app's own process or package, the foreground activity must be the
app's, the native first line must appear, and logs and a screenshot are
kept on every outcome; iOS checks the binary's platform and uses a fresh
simulator, deleted in a trap. Before committing:
- Run it once by `workflow_dispatch` on `main`; it gates `publish`
  (finding 3).
- `smoke-ios.sh:184-188` passes on "smoke: ok" and ignores the exit
  status, so a crash after the line (rc.2's Linux failure exactly) passes
  on iOS.
- `smoke-android.sh` has no `trap`; a `set -e` exit at `getprop` or
  `unzip` (`:128-136`) leaves `adb logcat` running and keeps no logs.
- The simulator's environment is written inline in `mobile.yml`;
  `src/scripts/mobile-env.sh`, "the one description of the build
  environment", knows only the two device targets.
- Check `git ls-files -s scripts/ci/smoke-*.sh` shows `100755` after
  `git add`; b161c1d exists because it did not once.
- An emulator is not a phone: SwiftShader under ARM translation can pass
  what fails on a Mali Android 11 (#312). Record its first result as the
  baseline.

**The failed-loop exit (`concat/src/lib.rs`).** Logging the error and

## 8. What is good, and should stay that way

- **The 11th's first recommendation worked the first time.** nextest
  with a per-test timeout (`src/.config/nextest.toml`) turned a
  ninety-minute silent hang into four named tests on its first Windows
  run, and the JUnit report is kept on failure.
- **The supply chain is one file.** `scripts/ci/deps.lock` pins 24
  downloads by digest, `fetch.sh` refuses and deletes a mismatch and
  prints both digests (`:66-78`), FFmpeg is a dated build, and a guard
  holds sherpa's pinned file to `Cargo.lock`'s version. Every action is
  pinned by SHA with its tag in a comment.
- **A release cannot publish what did not start.** Every desktop bundle
  is launched where it was built before upload; Windows' launch audits
  the bundle's imports against a must-ship list and cuts `PATH` to
  System32 (`smoke-windows.ps1:96-150`); Linux installs the `.deb` and
  runs the AppImage in clean Ubuntu and Debian containers and checks that
  start-up opens no CUDA library (`smoke-linux.sh:85-150`, #309); the
  release is a draft that needs every bundle and both phones.
- **Platform rules are pure functions of their inputs.**
  `dirs::convention` and `apple` (`dirs.rs:140-161`),
  `updates::windows_kind` (`:286-294`), `start::location_on`,
  `encodable_among` and `leads_with_hardware` with injected `opens` and
  environment (`encode.rs:442-479`): each platform's rule is tested on
  every runner, and b4adc57's tests panic if anything is opened.
- **Every native dialog has one seam.** `after_dialog` and
  `pick_files_then` (`host.rs:352-400`): a dialog runs with nothing
  borrowed, and the phone and the desk share the call.
- **Fonts are done properly.** Subset Noto faces with source and SHA-256
  per face (`fonts.rs:44-80`), each fallback once, and a test that every
  character of every shipped locale has a glyph.
- **The phone GPU path is coherent.** `limits_for` asks for the adapter's
  own limits where it is below WebGPU's (`gpu.rs:548-552`), the 8-bit
  working format follows into every pool, target and byte count, and the
  fallback is tested against the half-float picture to ±2 levels
  (`gpu/tests.rs:1825-1847`).
- **Device loss is finally tested end to end** through `render_on` with a
  dead lent compositor, redrawing the frame rather than dropping it
  (`concat-export/src/lib.rs:1517-1541, 2640-2706`).
- **`LivePaintings` is the right shape** (`titles.rs:116-190`): one
  policy, stamped per pass, a pure test and a test that fails under the
  old FIFO. The pool's held stills should copy it.
- **Honest reverts and honest messages.** 3178b78 says what failed and
  ships the known state; b161c1d, 2d3a43e and c06560e name the release
  candidate that found each bug, and `leave()`'s doc says what is guessed.
- **The 70 `unsafe` sites each carry a SAFETY line**, and concat-core is
  still free of `unsafe`.
