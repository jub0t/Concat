# Concat `src/` audit — 16 September 2026

Scope: the Cargo workspace under `src/` (14 crates, ~34k lines of Rust, ~14k lines of Slint), the GitHub issue tracker (112 issues, 28 open), CI history, and the ecosystem around the stack. Method: full read of the workspace manifests, the API/server crates, the project-folder and session code, the model table, CI workflows, and a complete line-by-line read of `concat-core` and `concat-project`; metrics over the whole tree (`grep`, `cargo clippy`, `cargo test`); issue and PR triage. Equivalent deep reads of `concat-media`, `concat-export`, `concat-host`, `concat-render`, `concat-effects` and the window were started but cut off by a usage limit, so those crates are covered by targeted checks and the tracker rather than an exhaustive sweep.

**Status after the fix pass (same day):** bugs 1, 3, 10, 12, 13, 14, 15, 17, 18 and the merge/numbering items of 20 are fixed in the working tree (see `git diff`); bug 4 needs the model mirror workflow run; bugs 2, 5-9 need reproduction on the reporters' platforms; bugs 11, 16 (a deliberate design choice, not a bug) and 19 are addressed by `ARCHITECTURE-PROPOSAL.md`.

## 1. Where the project stands

**Health at a glance**

| Signal | Value |
|---|---|
| Version / age | 0.2.2, repository created 25 Aug 2026 (3 weeks old, 435 commits) |
| Community | 2 490 stars, 216 forks, ~11 contributors, one author writes ~90% |
| Clippy (`--workspace --all-targets`) | 0 warnings |
| Tests | 345 `#[test]` functions across 14 crates; engine crates pass locally |

| `unsafe` blocks | 22, concentrated in `concat-android` (9), `concat-media` (8), `concat-speech` (3) |

| Largest files | `concat/src/studio.rs` 8 043 lines; `concat-export/src/lib.rs` 2 474; `commands.rs` 2 148 |

**Architecture is genuinely good for a three-week-old project.** The crate split is disciplined and the dependency arrows point one way: a std-only `concat-core`, one crate that knows FFmpeg exists (`concat-media`), the edit model with commands and undo (`concat-project`), a render plan with CPU and wgpu compositors (`concat-render`), export, a host layer, and a single API dispatcher (`concat-api`) that the CLI, the JSON-RPC/gRPC server and the window all drive. Effects are data (TOML manifest + WGSL + an FFmpeg chain string) rather than code, and 87 packages ship that way. Every model download is mirrored under the project's own release tag. That is a stronger foundation than most editors at this stage.

**The project has already pivoted once.** Git history shows a Tauri/React front end (`desktop/`) replaced by Slint, and the `engine/` tree renamed to `src/`. That churn explains several stale artefacts below.

**The weight is in the wrong place.** `studio.rs` (8k lines) is the window's controller, model, view-model and event bus at once; it is the most-changed file in the repository (76 commits). The engine crates are small, tested and clean; the window is where the open bugs live.

## 2. Bugs found

Ranked by impact. "Verified" means reproduced from source or a local run; "reported" means from the tracker with a plausible cause identified.

1. **CI on `main` is red (verified).** `concat`'s locale test fails: 20 English strings added by the Remote settings page and the Hologram effect have no translation in any of the 12 locales. `scripts/locales.py` was not run before commit `26bf590` and `86d4a5c`. Nightly builds are therefore skipped (the last five Nightly runs show `skipped`). Fix: run `python3 scripts/locales.py`, fill the locales, and add a pre-commit/CI step that fails on an out-of-date `en.json` *before* the long test job.

2. **Window freezes after clicking the "Concat" logo (reported, #99, duplicate #111).** Two independent Linux reporters; the app stops receiving pointer events. Symptom pattern is a modal/overlay left visible with `pointer-events` capturing, or the start screen swapped in while the editor's popup layer is still armed. Highest-priority UX bug: every user will click the logo.

3. **Project save is not crash-safe (verified, `concat-host/src/projects.rs:171-190`).** `save` writes `concat.json.saving` and renames it over the manifest, but never calls `sync_all` on the temp file before the rename. On ext4/APFS a power loss after rename can leave a zero-length manifest, and the code's own comment says a truncated manifest "loses the project". Issue #6 (data loss on malformed manifest) shows this class matters to users. One `file.sync_all()` fixes it.

4. **11 of 12 downloadable models have no digest (verified, `models/manifest.toml`).** Only `cutout-person` carries a sha256; every whisper, Kokoro and the object/brush cutout model is accepted unverified, which `SECURITY.md` explicitly lists as a threat it cares about. The Mirror models workflow computes digests but the results were never committed.

5. **60 fps export freezes partway (reported, #112).** A ~50 s timeline at 60 fps produces a file that freezes at 42 s; the same edit at 30 fps is fine. This landed after the mux/interleaver rewrite (`c88aebd`, `d591ddf`). Likely a DTS/PTS unit mismatch between the 60 fps video time base and the audio packet cadence in the interleaver's "whichever packet is due next" logic. The new e2e export suite (`concat-host/tests/export.rs`) runs only at the project default rate; add a 60 fps case.

6. **Audio export "End of file" on some sources (reported, #108, #59).** Partially addressed by PR #68 and the sample-count trim rewrite, but #108 is still open with a Peek screen capture (60 fps H.264 + AAC). Same family as bug 5; both point at `concat-media/src/audio.rs`, which has been rewritten 11 times in three weeks. It needs fixture-based tests against real oddities (edit lists, negative start PTS, VFR) rather than more patches.

7. **Double title bar on GNOME Wayland (reported, #97).** The window draws its own client-side decoration and never asks winit for `with_decorations(false)` on Wayland, or the request is made after the surface exists. Cosmetic but on every Ubuntu screen.

8. **Android/iPad layout collides with system bars and import does nothing (reported, #92).** Commit `15577c1` claims to keep out of the bars but a Redmi Pad and an iPad 9 both still show the overlap; the document picker is a JNI bridge (`concat-android/src/lib.rs`, 9 `unsafe` blocks) with no test coverage and no iOS equivalent.

9. **Loopback API trusts every local process (verified, `concat-server/src/lib.rs:60-84`).** A token is required only off loopback. With the Remote switch on, any process on the machine can read and write any file the user can, through `project.*`, `media.import`, `export.run` and `frame` with an arbitrary output path. That is the same trust model as most local dev servers, but it deserves a default token even on loopback (the window already knows how to mint one). Token comparison is also not constant-time.

10. **Documentation rot (verified).** `CONTRIBUTING.md` and `src/README.md` both tell contributors to read `ARCHITECTURE.md` first; it was deleted in `99f2293`. The `.cargo/config.toml` describes an optional `ffi` feature and a subprocess FFmpeg mode that no longer exist. The README's comparison table says "H.264 MP4 only" while the encoder supports HEVC and AV1.

### 2b. Edit-model bugs (`concat-project`, `concat-core`)

From a full read of both crates. Spot-checked in source where marked (v).

11. **Splitting or trimming a clip re-times every keyframe (v, `commands.rs:1226`, `:1276-1285`, `:1447`).** Keys, effect keys, speed-curve points and animation presets are stored as *fractions of clip length*. A split clones the whole animation into both halves, compressed into each half's span; a trim slides every key in absolute time; a merge stretches the head's keys over the new length. Scenario: a 10 s clip with an opacity fade over the first 5 s, split at 4 s, now fades over 2 s on the head and again over 3 s on the tail. This is the root of most animation oddities users will report and is a model change to fix (keys in clip-local seconds).

12. **Deleting a detached audio clip leaves the video permanently silent (v, `commands.rs:1894`).** `DetachAudio` sets the video's `muted = Some(true)`; only `ReattachAudio` clears it, and that is a no-op once the sound clip is gone. `ClipPatch` has no `muted` field, so nothing in the command surface can unmute. One-line fix: add `muted` to the patch.

13. **Splitting or freezing a reversed clip silently un-reverses it (v, `commands.rs:1261-1269`, `:1370-1374`).** The comment says the map "is not affine", but reverse *is* affine (`core/timeline.rs:303-312`); only speed curves need the mean fallback. Both halves play forward with no error. Commit `1ac2760` pinned this behaviour in a test, so it is design-endorsed data loss.

14. **Head trim on a reversed clip slides the picture (`commands.rs:1236`).** `source_start` advances by `moved × speed` regardless of `reverse`; for a reversed clip the head shows the far end of the source, so the correct edit leaves `source_start` alone.

15. **NaN is accepted by most numeric commands (v).** Only `SetClipKey` and `SetEffectKey` check finiteness (`commands.rs:1629`, `:1696`). `SetClipSpeed { speed: NaN }` stores a NaN speed and NaN duration; `SplitClips { time: NaN }` produces NaN durations on both halves. JSON cannot carry NaN, but `Command` is a public Rust API and the JSON-RPC layer accepts `1e999`-style overflow as infinity.

16. **Track names are dropped on load (`doc.rs:100-115`).** Legacy documents carry `"name"` on tracks; the `Track` struct no longer has the field, so reopening and saving an older project discards the names permanently.

17. **Reader and command clamps disagree (`doc.rs:247-273` vs `commands.rs:28`, `:1785`).** Minimum duration is 0.01 s on load but 1/60 s in commands; scale has no upper cap on load; offsets and rotation are not wrapped; speed-curve point speeds are unclamped. A hand-edited file can hold values no command could produce, while a comment in `lib.rs:1776` claims the opposite.

18. **Document version is written and never read (v, `doc.rs:33`, `:442`).** No migration table, no forward-compat passthrough of unknown fields on write. The "document this build cannot read" failures (#4, #12) will recur at the first breaking model change.

19. **Animation presets on the same property clobber instead of compose (suspected, `animation.rs:248-277`).** "Zoom In" plus a "Pulse" combo both write a scale key at `at = 0`; `value_at` takes the first and interpolates from the second, so the zoom vanishes.

20. Lower: `MergeClips` does not check `reverse`, `speed_curve`, `kind` or `audio_stream` before merging; `FreezeFrame` ripples only its own track, so detached audio drifts by the hold length; `next_numbered` concatenates every digit in a name ("Timeline 2 v10" → "Timeline 211"); core `Clip::range()` asserts on a negative duration and `Rational` arithmetic panics on i64 overflow even though `checked_new` exists.

What checked out: the rational time design, the arena, the cubic-bezier solver, speed-curve integration, id minting across loads, and the export boundary's frame-grid quantisation are all correct.

## 3. What is poorly designed

- **`studio.rs` is a God object.** 8 043 lines, 76 commits, holds every pane's state, every callback, the toast queue, the menu tokens, the server lifecycle and the preference persistence. There is no view-model layer between Slint models and engine state; state is mirrored by hand on every publish (`set_*` calls at lines 6247-7141). Every UI bug in the tracker lands here. Split by pane (media bin, timeline, inspector, monitor, settings) behind a small `Studio` façade, and put each pane's state behind a struct that owns its Slint model.
- **`unwrap` density in the model crate.** 154 unwraps in `concat-project/src/lib.rs` on a document that is user-editable JSON. Each one is a panic on a hand-edited or forward-version project file; with `panic = "abort"` in the `app` profile that is a crash, not an error dialog.
- **Two compositors, one truth.** CPU (`compositor.rs`) and wgpu (`gpu.rs`) paths must agree pixel-for-pixel; today parity is asserted by a handful of tests, and fixes like `a2fe39f` ("a branching effect chain opens on the CPU renderer") show they drift. Golden-frame tests with a perceptual threshold (SSIM/PSNR) across both paths would catch this class automatically.
- **Effects run through FFmpeg filter strings *and* WGSL.** Each package declares an `[ffmpeg] chain` template and a shader; the preview uses one, the audio path and some exports the other. The expression language in `expr.rs` is interpolated into filter strings; the crossed-bounds clamp panic fixed in PR #96 is the kind of bug that pattern breeds. Long term the roadmap's node-graph "mixers" cannot be built on string templates.
- **No frame cache or prefetch design.** Playback decodes on demand through `pool.rs`; the filmstrip regression (#52, 100% CPU on import) and the "strip caching" request (#57) are symptoms of no shared, bounded decoded-frame cache keyed by (media, time, size). Every professional editor has one.
- **Software decode only.** VideoToolbox is used for HEVC *encode*; there is no hardware *decode* on any platform, and issue #70 (VA-API hang on Intel) was "fixed" by not using VA-API. 4K H.265 phone footage will not scrub smoothly on laptops without it.
- **The timeline is drawn as one Slint element per clip** with the whole window redrawn on any dirty property (the Cargo.toml comment admits Skia partial rendering is off). PR #88 ("long clips crash the window with a wgpu texture-size error") shows lane textures are sized by clip length rather than viewport. Needs virtualisation: draw only the visible range, at viewport resolution.
- **Two edit models with the same type names.** `concat_core::timeline::{Project, Timeline, Track, Clip}` (rational time, arena ids) and `concat_project::model::{…}` (f64 seconds, string ids, a 40-field `Clip`) are unrelated types; every clip semantic is defined twice and translated in a third crate. All fields are `pub`, overlapping clips are permitted, and invariants such as "speed equals the curve's mean" are comments. Lookups are linear scans by `String` (`model.rs:1310`), `first_free_track` is tracks × clips.
- **`apply` is one 1 280-line match** (`commands.rs:866-2148`) with the 40-field `Clip` literal repeated three times; a new field is added in four places plus the reader.
- **Undo is a deep clone of the whole project per command** (`editor.rs:78`, depth 200) with no coalescing, so a drag emitting a command per mouse event produces a snapshot per event, and view state (`SelectTimeline`, `MoveTimeline`) lands in the undo history and the document.
- **Project file has no read schema version and no migration path.** The writer is derive-based and the reader is hand-walked, so the two schemas agree only by discipline; the version field is written and never read.
- **Dependency surface.** 835 crates, 67 at duplicate versions; `ort` pinned to a release candidate; three separate HTTP clients paths (ureq in host, ureq in speech, tonic/hyper behind `grpc`). Nothing runs `cargo audit` or `cargo deny` in CI.
- **Tests exist but the expensive ones are serialised** (`cargo test -j 1`, PR #110) because linking the `concat` test binary OOMs the runner. Engine tests should run in their own job so a window-crate link failure does not block them.

Good: `concat-core` (42 tests, time/arena/animate), `concat-media` (50, incl. real decode fixtures), `concat-project` (51), `concat-host/tests/export.rs` (every edit type exports end to end). Missing: anything for the window (`studio.rs`, 14 tests all in i18n/prefs), the Android bridge, the gRPC transport (5 tests), property tests for timeline invariants (no overlapping clips, non-negative durations), 60 fps / VFR / edit-list fixtures for the mixer, golden-frame comparisons between compositors, fuzzing of the manifest and package parsers.

## 5. Ecosystem research and what to adopt

Sources checked: crate registries and repositories for `ffmpeg-the-third`, `wgpu`, `slint`, `ort`, `whisper-rs`, `sherpa-onnx`; the Olive, Kdenlive/MLT, Shotcut, Cap, OpenCut and OpenTimelineIO projects; Flathub packaging guides. Items marked * were not re-verified today.

- **Hardware decode via FFmpeg's hwaccel API** is reachable from `ffmpeg-the-third` (it exposes `av_hwdevice_ctx_create` and `hw_frames_ctx`). VideoToolbox on macOS/iOS, D3D11VA on Windows, VAAPI on Linux behind an allow-list (the i915 hang in #70 argues for an opt-in toggle), MediaCodec on Android. Decoded frames can stay on the GPU and be imported into the shared wgpu device; on Metal this means zero-copy scrubbing.
- **Frame cache + render graph.** Olive 0.2 and Cap both key a bounded LRU by (source, timestamp, resolution) and render through a DAG so a parameter change invalidates only downstream nodes. This is also the natural substrate for the roadmap's effect/transition mixers and for keyframed effect parameters.
- **Colour management.** Issue #103 asks for full/limited range and Rec.2020; the HDR work in `9ef1b94` tags colour but does not convert it. OpenColorIO has no maintained Rust binding*; a smaller step is explicit linear-light compositing in the wgpu path with sRGB/BT.709 transfer in and out, which fixes blend and dissolve correctness at the same time.
- **Interchange.** OpenTimelineIO has a Rust crate (`opentimelineio-rs`*) and is the format DaVinci, Premiere and Kdenlive import. An OTIO export from `flatten.rs` is a weekend and opens the door to round-tripping.
- **Speech.** sherpa-onnx already ships in the binary and can run Whisper, SenseVoice, Moonshine and Parakeet models with word timestamps; consolidating captions onto it would drop whisper.cpp, its cmake build, and one of the two Metal contexts. Silero VAD (already prototyped in `test/silero_vad`) gives silence removal and a faster caption pre-pass. DeepFilterNet3 has a Rust crate (`deep_filter`) and an ONNX export for the "Noise removal" roadmap item.
- **Cutout.** RVM (GPL) is the person model; MODNet and BiRefNet* ship ONNX under permissive licences and handle objects. SAM2 small* replaces SlimSAM for the brush with better edges.
- **Untrusted WGSL.** Packages are user-installable. naga validation at load is in place; add a resource-limit check (bind groups, texture sizes, loop bounds are not statically bounded in WGSL) and run community shaders through a timeout on a throwaway device before they reach the monitor.
- **Plugins.** The roadmap wants sandboxed extensions. The WASM component model (`wasmtime` + WIT) is the only option that gives capability-based permissions for free; `extism` wraps it with a simpler ABI. Dynamic libraries via `abi_stable` give speed but no sandbox. MCP: the official `rmcp` Rust SDK sits naturally on `concat-api`'s dispatcher; PR #69 already prototypes 17 tools but re-implements the transport instead of reusing `concat-server`.
- **Distribution.** Flatpak with the `org.freedesktop.Platform.ffmpeg-full` extension solves #78 and the EGL/AppImage crashes (#30, #31); Windows code signing through SignPath's OSS programme or Azure Trusted Signing removes the SmartScreen wall; macOS is already notarised when secrets are set.
- **Testing.** Golden frames with SSIM thresholds (Kdenlive does this with MLT), `cargo fuzz` on `probe`, the TOML manifest parser and the JSON document loader, and `proptest` over `commands.rs` for timeline invariants.
