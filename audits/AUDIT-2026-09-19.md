# Concat `src/` audit — 19 September 2026

Scope: the Cargo workspace under `src/` (16 crates, 58.5k lines of Rust, 20.2k
lines of Slint), the tracker (87 issues, 38 open), CI, and everything that
landed since the 16 September audit and its proposal. Method: the proposal was
worked through step by step over three days; every step landed on `main` with
its tests green; this report is what was found on the way, what the numbers
say now, and what is still wrong. It follows the shape of
`AUDIT-2026-09-16.md` so the two can be read side by side.

**Status of the proposal:** every line of `ARCHITECTURE-PROPOSAL.md` is
ticked, each with a note on what it left for later. `ARCHITECTURE.md` is back
and describes the tree as it is now.

**The weight has moved.** Three days ago the window's controller was the
model, the view-model and the event bus at once. Ten of its concerns are now
panes behind one message loop, the engine gained a scheduler, a source-keyed
cache, proxies, hardware decode, one render description for both compositors
and a parity suite, the server mints tokens, and there is a performance table
with budgets. The gestures are what is left on the controller, and they are
the next cut.

**The engine found its own bugs.** The performance table's scrub scenario, on
its first run, showed one decode on the way back over covered ground. That was
two real defects (bugs 1 and 2 below), both older than the cache work, both
fixed the same hour. That is the argument for the table.

## 2. Bugs found and fixed this pass

Verified from source or a local run unless marked.

1. **Constant-rate files were indexed at a skewed rate (verified, fixed
   `381c477`).** The probe took `avg_frame_rate` first, which on a short or
   oddly-closed file is the frame count over a duration a frame short: ninety
   frames over eighty-nine thirtieths is 30.34 fps. Every frame landed a third
   of a frame early, boundary frames rounded up by one, and the cache had a
   hole at the skipped index, so every scrub back re-decoded there. A
   constant-rate stream now takes its base rate exactly when the two agree
   within two percent; a variable stream keeps its average.

2. **A request past a file's last frame walked from the keyframe every time
   (verified, fixed `381c477`).** A container that claims one frame more than
   it holds made the pool seek and decode to the end on each request for that
   index, since the answer was never remembered under it. It is now.

3. **The window did not build on `main` (verified, fixed `1147533`).** The
   Persian locale arrived with the locale table still declared thirteen long.
   The new file also lacked the inventory's newer keys, which the coverage
   test refuses; they are filled with English until a translator gets there.

4. **The crate's tests did not build on `main` (verified, fixed `796e9a9`).**
   The ripple-on-drop PR (#141) gave `AddClip` a `ripple` field and left three
   test initialisers without it. CI has been red since it merged.

5. **Two title bars on Linux (reported #97, #145, fixed `ad28218`).** Slint's
   winit backend re-applies the window's `no-frame` property after the window
   is made, over the attribute hook the window used, so on GNOME under Wayland
   the compositor's bar came back above the strip. The Slint window now says
   `no-frame` wherever the strip carries its own buttons. Not run on a Wayland
   desktop here; reasoned from the backend's source and the report.

6. **The loopback API trusted every local process (verified 16 Sept, fixed
   `e35b2d9`).** A token is minted when none is set, on loopback too; the
   comparison is constant-time; `version` reports `capabilities`.

7. **Touching an effect knob threw the clip's cached frames away (verified 16
   Sept, fixed `7311d2d`).** The cache keys on the source frame now.

8. **An import of twenty files ran twenty decoders (reported #52, fixed
   `ab70838`).** One scheduler with priorities and a reserved worker.

9. **Keys re-timed on split and trim (verified 16 Sept, fixed
   `cbd961e`).** Re-anchored in the four commands that move a clip's window.

## 3. Bugs still open

From the tracker, with what this pass learned about each.

1. **Logo click freezes the window (#99, #111).** Still open and still the
   highest-priority UX bug. The message loop now drops a result that arrives
   after its project closed in one place, which removes one class of cause,
   but the freeze itself has not been reproduced here. The next step is a
   Linux run with `SLINT_DEBUG_PERFORMANCE` and a log of the last callback
   before input stops.

2. **Windows exits silently with no compatible GPU adapter (#135).** The
   window acquires a device with `Backends::DX12` only and, without one, asks
   Slint for D3D by name (`platform.rs`), which refuses to start rather than
   fall back. Refusing to start was chosen so a silent CPU fallback would not
   hide a fault; it needs at least a message box before the exit, and an
   opt-in software path.

3. **Android export has no encoder (#130).** The Android build links a
   different FFmpeg; `VideoCodec::encoders` lists names the mobile build does
   not carry. Needs the mobile FFmpeg script to build x264 or MediaCodec
   encoding, and a test that every listed encoder exists on each target.

4. **Fade to black and white do not apply (#132).** Transitions are modelled
   in the plan now (`Transition::FadeTo`, `Shading`) and the compositors draw
   them, and the parity suite proves it, but the export still bakes fades into
   the decoder's FFmpeg chain. Filling the plan's `transitions` from the
   resolved transitions and dropping the chain is the fix, and it is the
   follow-up named in the proposal's §5 tick.

5. **Android and iPad layout (#92).** Not touched. The launch screen now has a
   phone shape; the editor's panes do not.

## 4. What is still poorly designed

- **The gestures.** `studio.rs` is 6 360 lines, and most of what remains is
  the drag, trim, razor, stage and brush machinery over the echo. It is one
  `Gesture` across the lanes and the stage, which is why it did not move with
  the panes. It should become its own module with a `Gesture` state machine
  and a test per gesture over a fake pointer.
- **Two shapes of the plan.** The plan can carry the crop, flips, transitions
  and mask, and the tests fill them, but the export still bakes the first
  three into the decoder and cuts the picture for the mask before planning.
  Until that moves, the decoder's chain and the plan can disagree, which is
  the drift the proposal set out to end.
- **`ExportClip` is still the wire type.** The CLI, the API and the title
  rasteriser speak it. Deleting it means the API takes the project model
  directly, which is a wire change.
- **Locales.** Fourteen locales, and the keys added this week are English in
  thirteen of them. The coverage test keeps that honest; it does not make it
  translated.
- **The Android crate has no tests** and nine `unsafe` blocks in a JNI bridge.
- **`unwrap` in the project crate's `lib.rs`** is mostly tests, but the file is
  2 957 lines of them and should split by concern the way `commands/` did.

## 5. Test coverage

429 tests in 75 files. What is held hard:

- Every edit exports, end to end, over synthetic media, and the suite crashes
  on purpose rather than tolerating a bad file (`concat-host/tests/export.rs`,
  four scenarios, ~35 s).
- The GPU matches the CPU reference on thirteen plans by SSIM, every one at
  0.9997 or better on this machine.
- The pool: eviction under budget, a scrub over covered ground decodes
  nothing, a proxy that vanished falls back, a request past the end is
  remembered.
- The scheduler: priority order, a reserved worker, a cursor that reverses.
- Hostile packages are refused at load; a table over budget too.
- Every locale covers the inventory.
- The panes' pure parts: rows are never reused, a marquee over zero columns,
  the zoom's limits and a NaN factor, the frame's size at every tier.

What is not covered: anything that needs a window (the repaint, the gestures,
the freeze in #99), Android, gRPC on CI (the feature builds and tests locally),
and the hardware decode paths on Windows and Android.

## 6. Performance, this machine

`cargo run -p concat-perf --release` on a 2023 MacBook, 19 September:

| Scenario | Measured | Budget |
|---|---|---|
| plan one frame of 200 clips on 4 tracks | 0.76 µs | ≤ 200 µs |
| 200 clip additions and 200 undos | 0.59 ms | ≤ 150 ms |
| save and open a 200-clip document (116 KB) | 1.90 ms | ≤ 60 ms |
| choose the visible clips of 200 for one publish | 0.22 µs | ≤ 50 µs |
| decode 1080p H.264 in software | 1 600 fps | ≥ 120 fps |
| decode 1080p H.264 on VideoToolbox | 308 fps | ≥ 120 fps |
| scrub forward over 90 frames, cold | 0.81 ms/frame | ≤ 25 ms |
| scrub back over covered ground | 0.24 µs/frame | ≤ 200 µs |
| decodes when an effect knob is turned | 0 | ≤ 0 |
| compose 1080p, 3 layers, sepia, CPU | 55 ms | ≤ 400 ms |
| compose 1080p, 3 layers, sepia, GPU with readback | 2.5 ms | ≤ 25 ms |
| export a 4 s 720p cut, two overlapping clips | 119 fps | ≥ 30 fps |

Hardware decode is slower than software here because the software decoder
runs on every core and the test file is a trivially-coded gradient; on real
4K H.264 the order reverses. The budgets are loose on purpose: they catch a
regression of two or three times, not a slow laptop.

## 7. Recommended order of work

1. Push `main` so CI goes green, and add the `--check` run of `concat-perf
   --quick` to the engine job.
2. Reproduce #99 on Linux with logging; it is the bug every user meets.
3. Fill the plan's crop, flips and transitions from the export and drop the
   decoder's chain for them; this closes #132 and ends the last two-path
   drift.
4. Move the gestures out of `studio.rs` into a state machine with tests.
5. A message before the exit, and a software path, for Windows without a
   usable adapter (#135).
6. The Android encoder (#130), with a test that every listed encoder links
   on every target.
7. Keep cached frames as textures in the GPU pool now that both compositors
   read a plan.
8. Translate the week's keys.
